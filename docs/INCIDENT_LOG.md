# 📋 บันทึกเหตุการณ์และบทเรียน (Incident Log)

> ทุกความผิดพลาดที่เคยเกิด พร้อม **กฎป้องกันถาวร** — ทำผิดซ้ำเรื่องที่บันทึกไว้แล้ว = บกพร่องร้ายแรงที่สุด
> **ก่อนแก้โค้ด อ่านหัวข้อ "กฎถาวรสรุป" ด้านล่าง** (อ่านจบในไม่กี่นาที) — สรุปบทเรียนจากทุกเหตุการณ์ รวมที่ย้ายไปคลังแล้ว
> รายการเต็มในไฟล์นี้เก็บ 31 วันล่าสุด · ของเก่าอยู่ใน [`docs/archive/incidents/`](archive/incidents/) แยกรายเดือน (เลข INC ยังอ้างได้เหมือนเดิม)
> หาเคสคล้าย: `grep -rn "<คำ>" docs/INCIDENT_LOG.md docs/archive/incidents/`

## 🛡️ กฎถาวรสรุป

> รวมกฎที่ซ้ำกันเป็นข้อเดียว · กฎที่ถูกยกเลิกหรือถูกแทนที่แล้วไม่อยู่ในสรุปนี้ · เลขในวงเล็บ = เหตุการณ์ต้นเรื่อง (ค้นได้ทั้งไฟล์นี้และคลัง)

### หลักร่วม (ใช้กับทุกงาน)

- ห้ามทางถอยที่ทำงานเงียบ: ข้อมูลหรือค่าตั้งที่จำเป็นหายไปต้องปฏิเสธพร้อมเหตุผล หรือให้บิลด์ล้ม ห้ามคืนค่าสำรองแล้วปล่อยผ่านโดยไม่มีใครรู้ (INC-0008 · INC-0101 · INC-0102 · INC-0155)
- กฎที่อยู่แค่ในเอกสารจะถูกละเมิดซ้ำ — กฎถาวรทุกข้อควรมีด่านอัตโนมัติ และสคริปต์ตรวจลงทะเบียนใน `CHECKS` ของ `repo:verify` ที่เดียว (INC-0005 · INC-0052 · INC-0129 · INC-0137)
- เอกสารเป็นปากทาง ไม่ใช่หลักฐาน — ก่อนบอกว่างานค้างหรือเสร็จ ให้รัน `npm run docs:status` แล้วยืนยันกับโค้ดและ `git log` (INC-0146 · INC-0229)
- ห้ามเขียน "ครบทั้งเว็บ / 100% / สะอาดแล้ว" ถ้าไม่ได้แนบคำสั่งสแกนหรือผลยิงตรวจของจริงที่คนถัดไปรันซ้ำได้ · บั๊กที่เจอในจุดหนึ่งให้ไล่ทั้งคอมโพเนนต์ (INC-0115 · INC-0127b · INC-0252)
- ตัดสินจากการวัดจริงเท่านั้น: วัดก่อน/หลังบน production build ที่ hydrate แล้ว ห้ามเชื่อคำแนะนำหรือตัวเลขประเมินโดยไม่วัด A/B (INC-0061 · INC-0103b · INC-0159)

### Git · PR · CI · deploy

- งานจบเมื่อ PR ถูกเปิดแล้วเท่านั้น ไม่ใช่ตอน push — ใช้ `npm run pr:auto` ถ้าไม่มี `gh` ให้เปิดผ่าน API แล้วรายงานข้อจำกัด ห้ามอ้างว่าผู้ใช้ไม่ได้สั่ง (INC-0015 · INC-0043 · INC-0044)
- หนึ่งกิ่งต่อหนึ่งงาน ดึง `origin/main` ก่อนเริ่ม จบด้วย `pr:auto` แล้ว `git:tidy` · `npm run commit` stage เฉพาะไฟล์ที่ล็อก ไฟล์ใหม่ต้องขยาย `agent:lock` · push เมื่อ `git status` สะอาด (INC-0017 · INC-0069 · INC-0157)
- workflow ที่ต้องปลุกอีก workflow ใช้ `workflow_dispatch` (push จาก GITHUB_TOKEN ไม่ปลุก) · ตรวจว่ามี run ของ deploy.yml สำหรับ commit นั้นจริง ไม่ใช่ดูแค่ว่า merge แล้ว (INC-0006)
- แก้ `.github/workflows/` ผ่าน PR ที่ CI รันจริงเท่านั้น · ขั้นสำคัญ fail-fast ห้ามกลืน error · อัปรุ่นหลักของ Action ต้องอ่านค่าเริ่มต้นที่เปลี่ยนและดู CI รอบแรก (INC-0020 · INC-0022 · INC-0078 · INC-0206)
- ใช้ npm กับ `package-lock.json` เท่านั้น: ติดตั้งแบบบังคับ lockfile · Action ตรึงด้วย SHA · import ทุกตัวต้องประกาศใน package.json (`test-ci-supply-chain`) (INC-0191 · INC-0206 · INC-0258)
- ทุกขั้นใน CI ที่ build หรือตรวจผลบิลด์ต้องได้ env ชุดเดียวกับขั้น deploy (รวม `NEXT_PUBLIC_*`) และค่า NEXT_PUBLIC ที่ว่างต้องเตือนตอน deploy (INC-0100 · INC-0101 · INC-0115)
- คีย์ใหม่ใน `wrangler.jsonc` เทียบ config-schema ก่อน · binding ที่ deploy ตรวจผ่าน API ต้องเช็กสิทธิ์ token · secret ใหม่ต้องครบ: โค้ด · env ในขั้น deploy · `docs/PENDING_SETUP.md` (INC-0034 · INC-0066 · INC-0152)
- ห้าม dependabot ยก Next เอง — ยกคู่กับ OpenNext แล้วลอง build + `wrangler dev` ก่อน · rollback ต้องระบุ Version ID ของบิลด์ก่อนหน้า (INC-0285)
- สคริปต์อัตโนมัติ: `gh` ใส่ `-R owner/repo` · ใน worktree ใช้ `checkout --detach` · ห้าม track ไฟล์ที่เครื่องมือสร้างใหม่ทุก commit · คำสั่งที่มี secret ให้คนก๊อปใช้ heredoc (INC-0004 · INC-0012 · INC-0035 · INC-0047)

### ด่านตรวจ (วิธีเขียนและพิสูจน์)

- ด่านใหม่ต้องพิสูจน์ว่าตกได้จริง (รันกับโค้ดก่อนแก้หรือใส่บั๊กกลับ) และต้องตรวจการต่อสายถึงปลายทาง ไม่ใช่แค่ว่าไฟล์หรือฟังก์ชันมีอยู่ (INC-0129 · INC-0138 · INC-0140 · INC-0195)
- ด่านห้ามผ่านเมื่อไม่ได้ตรวจ: ไฟล์หาย คลังว่าง สแกนศูนย์ไฟล์ ค่าวัดได้ 0 หรือจบเงียบ = ตก ห้ามห่อด้วย `if existsSync` (`test-gate-integrity`) (INC-0133 · INC-0165 · INC-0171 · INC-0186 · INC-0189b)
- ด่านที่พึ่งเครื่องมือภายนอกต้องแยก "ตรวจไม่ได้" ออกจาก "ไม่ผ่าน" · ด่านที่ต้องให้คนติดตั้งเองถือว่าไม่มีด่าน ต้องผูกกับ `npm install` (INC-0043 · INC-0044)
- งานที่ผลขึ้นกับ build ต้องตรวจ artifact จริง (dist/ · .next) ไม่ใช่ source · ด่านที่อ่านบิลด์วางหลังขั้น build และล้าง `.next` ก่อนไล่ผล (INC-0108 · INC-0110 · INC-0133 · INC-0136)
- เรียกฟังก์ชันหรือเรนเดอร์ของจริงแล้วตรวจผล แทนการสแกนซอร์สด้วย regex · ตรรกะที่ต้องเทสต์แยกเป็นโมดูลล้วน ไม่เรียก `main()` ตอน import (INC-0114 · INC-0116 · INC-0129 · INC-0245)
- จับข้อความให้แม่น: แอตทริบิวต์จับพร้อม `="` · ตัดคอมเมนต์ก่อนค้น · เทียบชื่อด้วยขอบเขตคำ · ระวังตัวพิมพ์ เช่น fetchPriority · หามาร์กอัปไม่เจอให้ตก (INC-0110 · INC-0130 · INC-0187 · INC-0207 · INC-0211)
- เปลี่ยนแนวทางแก้เมื่อไรต้องแก้ด่านให้ล็อกทางแก้ใหม่ ห้ามปล่อยด่านล็อกวิธีเดิมจนกันการหาต้นเหตุจริง (INC-0109 · INC-0158)
- เทสต์สุ่มหรือเทียบเวลารันซ้ำอย่างน้อย 20 รอบก่อนขึ้น CI · ค่าเฉลี่ยของชุดว่างไม่ใช่ 0 ต้องพิมพ์ขนาดตัวอย่างกำกับ · ลองเครื่องมือวัดกับข้อมูลจริง (INC-0007 · INC-0135 · INC-0207 · INC-0234)
- งบตัวเลขในด่านตั้งจากค่าที่ CI วัดได้ + เผื่อราว 10% และรัดลงได้อย่างเดียว · คอมเมนต์ตัวเลขต้องตรงค่าในโค้ด (`TUNED_CONSTANTS`) (INC-0103b · INC-0161 · INC-0169 · INC-0196)

### เอกสารและบันทึก

- สถานะแผนแก้ที่บรรทัด `> **สถานะ**:` แล้วรัน `npm run docs:index` ตารางต้องตรงผลทุกไบต์ · ตัวเลขเขียนติดหน่วยให้ด่านอ่านออก ห้ามใส่จำนวนด่านในชื่อขั้น workflow (`test-docs-numbers`) (INC-0119 · INC-0146 · INC-0229)
- เลข INC ห้ามซ้ำและที่อ้างถึงต้องมีจริง (ชนเลขให้รายการที่บันทึกทีหลังเติม `b`) · บันทึก incident ทุกช่องต้องมีเนื้อจริง `validateIncident()` บล็อกให้ (INC-0021 · INC-0145)
- ผลตรวจที่ยังไม่แก้ห้ามขึ้น repo สาธารณะ · API ใหม่ชุดใหญ่หรืองานที่แตะเงิน สิทธิ์ ข้อมูลส่วนบุคคล ต้องผ่านรอบตรวจข้ามระบบก่อนปิดแผน (INC-0289)
- ชื่อสิทธิ์หรือค่าตั้งของผู้ให้บริการภายนอกต้องเปิดเอกสารยืนยันก่อนเขียนลงคู่มือ ห้ามอนุมานจากชื่อที่คล้าย (INC-0204)

### Cloudflare · Worker · แคช · D1 / KV / R2

- บน Workers ห้ามพึ่ง state ในหน่วยความจำข้ามคำขอ (รวม Map นับ rate limit) — สถานะรอบอ่านส่งเป็น token ที่เซ็นด้วย secret จาก env จริง หรือเก็บใน KV/D1 (INC-0009 · INC-0010 · INC-0184)
- ตัวนับที่กันค่าใช้จ่ายหรือการเดารหัสใช้ `INSERT … ON CONFLICT … RETURNING` บน D1 แบบ atomic ห้ามอ่านแล้วเขียนทับบน KV ห้าม peek ก่อนนับ (INC-0221 · INC-0230)
- D1: UPDATE/DELETE เช็ก `meta.changes` ก่อนตอบสำเร็จ · เช็กก่อน INSERT ใช้ขอบเขตเดียวกับ UNIQUE INDEX · สคีมามาจาก `migrations/` เท่านั้น · ตอน D1 ล่มทำตาม `DB_FAILURE_POLICY` (INC-0048 · INC-0068 · INC-0077 · INC-0303)
- `_headers`: กฎ path ที่ซ้อนกันถูกต่อค่าไม่ใช่แทนที่ · แคช immutable ต้องระบุนามสกุลไฟล์ · ห้าม regex ซับซ้อนใน `next.config.ts` · ตรวจด้วย `curl -sI` หลัง deploy (INC-0003 · INC-0083b · INC-0084 · INC-0166)
- `run_worker_first` ต้องครอบทุกหน้า Next · ชื่อ chunk ใต้ `/_next/static` ห้ามมีอักขระนอกชุดปลอดภัย (`test-worker-first-routes`) (INC-0188 · INC-0225 · INC-0264b)
- redirect ของเส้นทางสาธารณะเป็น 301/308 เสมอ วัดด้วย `curl --max-redirs 0` · www ไปโดเมนหลักมีกฎสองชั้นผูกกับ deploy (`test-canonical-host`) (INC-0203 · INC-0225 · INC-0300)
- ค่าตั้งใน dashboard (CSP · WAF · บอต) ต้องมีสคริปต์อ่านของจริงมาเทียบ · ก่อน PUT ต้อง GET เก็บสแนปช็อต ส่งกลับทั้งก้อน แล้วเทียบทีละฟิลด์เมื่อสถานะนิ่ง (INC-0115 · INC-0179 · INC-0180 · INC-0205)
- นโยบายบอต: `ai_bots_protection` = block · `fight_mode` = false · ห้ามบล็อกบอตค้นหาและบอตพรีวิวโซเชียล (`test-bot-policy`) · ห้ามสรุปว่าบอตโดนบล็อกจาก curl ด้วย UA ปลอม (INC-0105 · INC-0177 · INC-0180)
- งานที่ยิงเข้า production จากภายนอก (cron · webhook) ต้องยิงจริงจากเครื่องตัวจริง · cron ยิงเข้า workers.dev ตั้ง User-Agent เอง และอ่านเนื้อ 403 แยกจาก 401 (INC-0141 · INC-0142)
- Service Worker: ตรวจ "การเปิดหน้าเว็บ" ก่อนกฎคำนำหน้าเส้นทาง · ผู้เข้าครั้งแรกต้อง reload 0 ครั้ง · เวอร์ชันแคชเปลี่ยนเองทุก deploy (`test-sw-reload`) (INC-0096 · INC-0164 · INC-0188b)
- แคชหน้า Next ห้ามใช้ KV · ชื่อ KV binding ต้องตรงกับโค้ด · กฎ lifecycle ของ R2 อยู่ในโค้ดที่ deploy.yml รันทุกรอบ ห้ามตั้งมือ ห้ามครอบ `studio-logo/` (INC-0287 · INC-0304)

### Astro · Next · บันเดิล · ความเร็ว

- island ห้าม import ข้อมูลก้อนใหญ่ (`@/data/cards`) — สำรับโหลดขนานกับ `/shuffle` · ไฟล์ "use client" ห้ามลาก platform/db เข้าบันเดิลแม้ทางอ้อม (`test-code-debt`) (INC-0121 · INC-0225 · INC-0226)
- ส่ง prop ให้ client component เฉพาะฟิลด์ที่ใช้จริง (ทุกไบต์ลง payload) · client component ที่อ้างจาก root layout มีต้นทุนทุกหน้า (INC-0103 · INC-0103b)
- งบน้ำหนักนับทั้ง JS · CSS · ฟอนต์ที่พรีโหลด · จำนวน DOM หน้าแรก และมีเส้นตัวแทนของหน้ารายรายการ · หน้า Astro ที่ไม่มี island ต้องไม่มี React (`test-bundle-budget`) (INC-0121 · INC-0187 · INC-0228 · INC-0247)
- เพิ่มเครื่องมือเรนเดอร์ใหม่ต้องเพิ่มวิธีนับในด่านงบ · ย้ายหน้าข้ามเครื่องมือต้อง diff `<head>` บิลด์เดิมกับใหม่ทีละหน้า รวมช่องที่เคยสืบทอดจาก layout (INC-0165 · INC-0168 · INC-0170)
- root layout ของ Next ห้ามเรียก getServerLocale/headers/cookies และห้ามมี middleware (`test-seo-wave4`) · ลิงก์ไปหน้า Astro ห้าม import `next/link` ตรง (`test-astro-routes`) (INC-0091 · INC-0167)
- ห้าม prefetch ไม่มีเงื่อนไข: ลิงก์ในกริด รายการใหญ่ และของที่อยู่ทุกหน้าใส่ `prefetch={false}` · Speculation Rules สร้างจากโมดูลกลาง ห้าม eager (`test-prefetch-loop`) (INC-0087 · INC-0106 · INC-0123b · INC-0159)
- ของที่อยู่ทุกหน้าห้ามยิง `/api` ให้ผู้ชมที่ไม่ล็อกอิน (ใช้คุกกี้ใบ้) · ผู้ล็อกอินยิง auth/me ครั้งเดียว · ปุ่มบัญชีห้าม fetch (`test-request-budget`) (INC-0104 · INC-0116 · INC-0198)
- แถบยินยอมคุกกี้: markup มากับ HTML ซ่อนด้วย CSS ตั้งค่าด้วยสคริปต์ใน head ห้าม useEffect · ห้าม preconnect ไปโฮสต์ AI · สคริปต์ head ที่แตะ html ใส่ suppressHydrationWarning (INC-0158 · INC-0261)
- ของใน RootHtml / globals.css / fonts.ts กระทบทุกหน้า วัดทั้งหน้าเนื้อหายาวและหน้าแอป · TBT แยกรายโดเมนก่อนโทษโค้ดเรา · CSS รายหน้าห้ามเข้า Early Hints (INC-0160 · INC-0172 · INC-0266)
- วัดความลื่นบนบิลด์จริงที่ hydrate แล้ว บนมือถือจำลองที่หน่วง CPU 4–6 เท่า ไม่ใช่ดูด้วยตาบนเดสก์ท็อป · นับเลเยอร์ GPU ด้วย CDP LayerTree (INC-0060 · INC-0128 · INC-0244 · INC-0273)
- หน้าที่ DOM ใหญ่ห้าม `showModal()` กับหน้าต่างที่เปิดบ่อย (ใช้ `show()` + ดักโฟกัสเอง) · สร้างหน้าต่างที่เปิดแน่ล่วงหน้าตอนเครื่องว่าง · ห้ามสร้าง AudioContext ในเฟรมแตะ (INC-0301)
- ห้ามอ่านขนาด layout ตอนสคริปต์เริ่มหรือ mount (ใช้ ResizeObserver) · ห้ามเขียนค่าเดิมซ้ำลง `<html>` ตอน hydrate · ห้ามเขียนตัวแปร CSS ลง container ใหญ่ใน scroll/rAF (INC-0247 · INC-0248 · INC-0272)

### Hydration · island · state ฝั่งหน้าเว็บ

- เรนเดอร์แรกของคอมโพเนนต์ที่ SSR ต้องเหมือนกันทั้งสองฝั่ง — ค่าเริ่มต้นของ state ห้ามอ่าน matchMedia / localStorage / window / แคชระดับโมดูล (INC-0075 · INC-0293)
- สคริปต์ธรรมดาที่แตะ DOM ใน island ต้องรอสัญญาณ hydrate จาก island · ยืนยันการแก้ hydration ด้วย `astro dev` ที่ React ไม่ย่อ (INC-0296)

### บัญชี · ล็อกอิน · ความเป็นส่วนตัว

- ทุก route อ่านเซสชันผ่าน `getSessionUser()` (ตรวจการเพิกถอน) · origin ผ่าน `resolveAppOrigin()` ที่ whitelist โฮสต์ ห้ามเชื่อ x-forwarded-host (`test-session-guard`) (INC-0042 · INC-0201)
- secret ของ auth ใน production สั้นกว่า 32 ตัวต้อง throw · OAuth ต้องตรวจ state cookie · ปลายทางหลังล็อกอินเก็บในคุกกี้ กัน open redirect (INC-0029 · INC-0036 · INC-0144)
- แยก "ระบบตั้งค่าไม่ครบ" (503) ออกจาก "ข้อมูลผิด" (401 ข้อความกลาง) · ไม่มี `PASSWORD_PEPPER` ต้องโยน error · แฮชผ่าน `npm run auth:hash` · PBKDF2 บน Workers ไม่เกิน 100,000 รอบ (INC-0045 · INC-0046 · INC-0049)
- token ใช้ครั้งเดียวเผาหลังผ่านทุกเงื่อนไข · ลิงก์ GET ห้ามออกคุกกี้เซสชัน · สิทธิ์ไม่จำกัดต้องยืนยันอีเมล · บัญชีที่ยังไม่ยืนยันอีเมลไม่ใช่หลักฐานความเป็นเจ้าของ (INC-0074 · INC-0221)
- ลบบัญชีแล้วสมัครหรือ OAuth ด้วยอีเมลเดิมต้องคืนชีพแถวเดิม · การลบต้องล้างข้อมูลส่วนบุคคลจริงรวมตารางลูก (`test-email-auth`) (INC-0048 · INC-0202 · INC-0220 · INC-0226)
- แบนเนอร์สถานะล็อกอินต้องตรวจเซสชันจริงและล้าง query ที่ใช้แล้ว · เปลี่ยนที่เก็บข้อมูลต้องไล่ข้อความเรื่องข้อมูลส่วนบุคคลทุกหน้าให้ตรงกัน (INC-0050 · INC-0295)
- อีเมล digest: GET ห้ามยกเลิกรับเอง (สแกนเนอร์กดลิงก์) ใช้ POST + หัว List-Unsubscribe · การส่งอีเมลมี timeout · ข้อมูลผู้ใช้ในอีเมลต้อง escape (INC-0222 · INC-0226)
- ทุก route อ่าน JSON ด้วย `request.json().catch(() => null)` แล้วตรวจชนิด · สคีมาสาธารณะกำหนดขอบเขตความยาวและอาร์เรย์ (INC-0031 · INC-0147)

### โค้ดทั่วไป

- เวลากรุงเทพฯ ผ่านโมดูลกลาง ห้ามบวก 7 ชั่วโมงเอง · คีย์ localStorage ผ่าน `STORAGE_KEYS` · catch ว่างต้องมีคอมเมนต์อธิบาย (`test-code-debt`) (INC-0193 · INC-0201)

## 📐 วิธีบันทึก

แก้บั๊กแล้ว commit ด้วย `npm run commit -- --type fix` (หรือ `hotfix` / `revert`) — `scripts/git-author-guard.ts` บันทึกลงไฟล์นี้ให้เอง และ **บล็อก commit** ถ้าขาด `--symptom` `--cause` `--prevention` หรือเนื้อหาแต่ละช่องลอกหัวข้อมา (`validateIncident()` ใน `scripts/incident-log.ts`)

```bash
npm run commit -- --agent <ชื่อ> --type fix --scope <หมวด> \
  --msg "<แก้อะไร>" \
  --symptom "<สิ่งที่คนเจอเห็น — ไม่ใช่ชื่อเรื่อง>" \
  --cause "<ทำไมหลุดมาได้ตั้งแต่แรก — สาเหตุราก ไม่ใช่อาการ>" \
  --prevention "<กฎถาวร/ด่านตรวจที่ทำให้ไม่เกิดซ้ำ>" \
  --severity high --verify "<คำสั่งที่รัน + ผลที่ยืนยันว่าหาย>"
```

ปัญหาที่ไม่ได้มาจาก commit (process · automation) หรือ commit ด้วย `git` ตรง ๆ: `npm run incident -- --title "…" --severity high --symptom "…" --cause "…" --fix "…" --prevention "…" --verify "…"`

- `อาการ` เขียนแบบคนยังไม่รู้คำตอบ · `สาเหตุราก` ตอบว่า "ทำไมถึงหลุดมาได้" · `กฎป้องกัน` ถ้าได้ให้เป็น **ด่านตรวจอัตโนมัติ** ไม่ใช่แค่ "ให้ระวัง"
- เกี่ยวกับเหตุการณ์เก่าให้ใส่แถว `เชื่อมโยง` / `เกิดซ้ำแล้ว`
- กฎใหม่ที่ยังไม่มีในหัวข้อ "กฎถาวรสรุป" ให้เติมบรรทัดเดียวในหมวดที่ตรง พร้อมเลข INC (ใน PR เดียวกัน)
- เลขซ้ำ: ผู้บันทึกทีหลังเติมท้ายด้วย `b` (เช่น `INC-0136b`) — ด่าน `test-docs-numbers` ตรวจเลขซ้ำและเลขที่อ้างแต่ไม่มีจริง ทั้งไฟล์นี้และคลัง
