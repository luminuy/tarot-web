# 📜 ร่างข้อตกลงการประมวลผลข้อมูลส่วนบุคคล — Reader Studio (ร่าง ยังไม่ใช่ฉบับใช้จริง)

> **สถานะ**: ⏸️ ร่างโดยทีมพัฒนา — **ต้องให้เจ้าของ/ทนายตรวจและแก้ก่อนเปิดใช้จริง**
> รุ่นในโค้ด: `STUDIO_DPA_VERSION = "draft-2026-10-06"` (`src/lib/studio/dpa.ts`)
> สตูดิโอปิดอยู่จนกว่าจะตั้ง `READER_STUDIO_ENABLED=1` · เมื่อได้ฉบับจริง ให้เปลี่ยน `STUDIO_DPA_VERSION` + `STUDIO_DPA_POINTS_TH`
> แม่หมอทุกคนจะถูกขอให้ยอมรับใหม่อัตโนมัติ (รุ่นไม่ตรง = ยังไม่ยอมรับ)

## 1. คู่สัญญาและบทบาท (ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562)

| บทบาท | ใคร | หน้าที่หลัก |
|---|---|---|
| ผู้ควบคุมข้อมูล (Data Controller) | แม่หมอผู้ใช้สตูดิโอ | กำหนดวัตถุประสงค์ · ขอความยินยอมจากลูกค้า · ตอบคำขอใช้สิทธิของลูกค้า |
| ผู้ประมวลผลข้อมูล (Data Processor) | SeerTarot | เก็บและประมวลผลตามคำสั่งของแม่หมอเท่านั้น · รักษาความปลอดภัย |

## 2. ข้อมูลที่ประมวลผล

- ชื่อที่ใช้เรียกลูกค้า · ช่องทางติดต่อ (ถ้าแม่หมอกรอก) · บันทึกส่วนตัวของแม่หมอ
- คำถามของลูกค้า · ไพ่ที่เปิด · โน้ตและคำอ่านของแม่หมอ
- สถิติการเปิดลิงก์ (จำนวนครั้งเท่านั้น — ไม่เก็บ IP หรือข้อมูลอุปกรณ์ของผู้เปิด)

## 3. สิ่งที่ระบบบังคับใช้จริงแล้ว (ตรวจได้ในโค้ด)

| ข้อ | การบังคับใช้ | ที่อยู่ในโค้ด |
|---|---|---|
| แยกข้อมูลรายแม่หมอ | ทุกคำสั่งฐานข้อมูลกรองด้วย `reader_id` | `src/lib/studio/studio.repo.ts` |
| ไม่ใช้ข้อมูลเพื่อการอื่น/ไม่ฝึกโมเดล | ส่งให้ AI เฉพาะโน้ต + คำถาม (ซ่อน PII ก่อน) — ไม่ส่งชื่อ ช่องทางติดต่อ หรือบันทึกส่วนตัวของลูกค้า | `src/lib/studio/draft.ts` |
| ซ่อนข้อมูลอ่อนไหวก่อนส่ง AI | `redactPii` (เลขบัตรประชาชน · เบอร์โทร · อีเมล · บัตร · บัญชี) | `src/lib/security/pii.ts` |
| ลบได้ทันที | ลบลูกค้าทั้งคน = ลบคำอ่านและลิงก์ทั้งหมด · ลบบัญชีแม่หมอ = ลบข้อมูลสตูดิโอทั้งหมด | `deleteClient` · `deleteReader` |
| ส่งออกได้ | ส่งออกข้อมูลรายลูกค้าเป็น JSON | `GET /api/marketplace/studio/clients/[id]` |
| ลิงก์ปลอดภัย | โทเคนสุ่ม 128 บิต เก็บแค่แฮช · หมดอายุ 7/30/90 วัน · รหัสผ่านได้ · เพิกถอนได้ · noindex · ไม่ส่ง Referer | `src/lib/studio/share.ts` · `/r/[token]` |
| ความโปร่งใสเรื่อง AI | บรรทัด "เรียบเรียงด้วยความช่วยเหลือของ AI" เปิดเป็นค่าเริ่มต้น | `show_ai_disclosure` |

## 4. ประเด็นที่ทนายต้องตัดสิน (ยังไม่มีในร่าง)

1. ระยะเวลาเก็บรักษาข้อมูลหลังแม่หมอเลิกใช้ (ปัจจุบัน: เก็บจนกว่าจะลบ)
2. การแจ้งเหตุละเมิดข้อมูล — ระยะเวลาและช่องทางแจ้งแม่หมอ (กฎหมายกำหนดผู้ควบคุมแจ้ง สคส. ภายใน 72 ชม.)
3. ผู้ประมวลผลช่วง (Sub-processor): Cloudflare (โฮสต์/ฐานข้อมูล) · Google Gemini (เรียบเรียงข้อความ) — ต้องระบุในสัญญาหรือไม่ และเงื่อนไขการโอนข้อมูลไปต่างประเทศ
4. ความรับผิดเมื่อแม่หมอบันทึกข้อมูลโดยไม่ได้รับความยินยอม
5. เงื่อนไขแพ็กเกจรายเดือน (เมื่อเจ้าของตั้งราคาใน Stripe)

## 5. ข้อความที่แม่หมอเห็นตอนยอมรับ (ฉบับร่างในโค้ด)
