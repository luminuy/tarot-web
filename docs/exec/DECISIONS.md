# บันทึกการตัดสินใจและการทดลองของผู้บริหาร (Executive Decision Log)

> ผู้ช่วย `cmo` · `coo` · `cto` (`.claude/agents/`) **ต้องอ่านไฟล์นี้ก่อนเสนออะไรทุกครั้ง** — เรื่องที่ตัดสินไปแล้วห้ามเสนอซ้ำ
> เว้นแต่มีหลักฐานใหม่ที่ทำให้เหตุผลเดิมไม่จริงแล้ว (ต้องบอกว่าหลักฐานใหม่คืออะไร)
>
> ผู้ช่วยทั้ง 3 ตัวเขียนไฟล์ไม่ได้ — ให้เสนอบรรทัดใหม่ในหัวข้อ "เสนอบันทึกลง DECISIONS.md" ท้ายคำตอบ
> แล้วเจ้าของหรือเซสชันหลักเป็นผู้จดลงตาราง (เพิ่มแถวใหม่ไว้บนสุดของตาราง)

## วิธีจด

| ช่อง | เขียนอะไร |
|---|---|
| วันที่ | วันที่ตัดสินใจ (ปี ค.ศ.) |
| ฝ่าย | `cmo` · `coo` · `cto` · `เจ้าของ` |
| เรื่อง | ตัดสินว่าทำ/ไม่ทำอะไร หรือทดลองอะไร — ประโยคเดียว |
| เหตุผลและหลักฐาน | ตัวเลขหรือไฟล์ที่ใช้ตัดสิน (มีวันที่ของข้อมูล) |
| สถานะ | `ตัดสินแล้ว` · `กำลังทดลอง (วัดอะไร ครบวันไหน)` · `ได้ผล` · `ไม่ได้ผล` · `ยกเลิก` |
| ทบทวน | วันที่ควรกลับมาดูใหม่ หรือ `-` ถ้าไม่ต้อง |

- การทดลองต้องบอก **ตัวชี้วัดและวันครบกำหนด** ตั้งแต่วันที่เริ่ม — ครบแล้วแก้สถานะเป็น `ได้ผล` / `ไม่ได้ผล` พร้อมตัวเลข ห้ามลบแถว
- แถวที่จดแล้วเป็นประวัติ: เหตุผลและหลักฐานเป็นข้อมูล ณ วันที่ของแถว แก้ได้เฉพาะช่องสถานะกับทบทวน · ตัดสินใหม่ทับเรื่องเดิม = เพิ่มแถวใหม่แล้วเปลี่ยนสถานะแถวเก่าเป็น `ยกเลิก`
- ก่อนอ้างแถวไหนกับเจ้าของ ให้ตรวจของจริงก่อน (โค้ด · `git log`) — ไฟล์นี้บอกว่าตัดสินอะไร ไม่ได้พิสูจน์ว่าระบบตอนนี้เป็นอย่างนั้น
- ห้ามจดอีเมล ชื่อลูกค้า หรือค่า secret ลงไฟล์นี้
