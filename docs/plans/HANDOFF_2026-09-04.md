# 🔴 1. ISSUE-018 · ตั๋วคิวแม่หมออ่านได้ด้วย `customerRef` ที่ส่งมาใน query string

## บริบท

`customerRef` เป็น **ความลับแบบ bearer** (ใครถือ = เป็นเจ้าของตั๋ว) แต่ถูกออกแบบให้ส่งผ่าน URL

`src/components/marketplace/BookQueueModal.tsx:38-46` สร้างและเก็บไว้ใน localStorage:

```ts
const getCustomerRef = (): string => {
  if (typeof window === "undefined") return "cust_anon";
  let ref = localStorage.getItem("tarot_customer_ref");
  if (!ref) {
    ref = `cust_${crypto.randomUUID().replace(/-/g, "").slice(0, 16)}`;
    localStorage.setItem("tarot_customer_ref", ref);
  }
  return ref;
};
```

`src/app/api/marketplace/tickets/route.ts:29-42` — **ไม่ตรวจ session เลย**:

```ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const customerRef = searchParams.get("customerRef");
  if (!customerRef) {
    return NextResponse.json({ error: "ต้องระบุ customerRef" }, { status: 400 });
  }
  const tickets = await listActiveTicketsForCustomer(customerRef);
  return NextResponse.json({ tickets });
}
```

`src/app/api/marketplace/tickets/[id]/route.ts` — `GET` คืนทั้งแถวโดยไม่ตรวจอะไรเลย (`nickname`, `question`, `readingSnapshot` และบทสรุปจาก AI)

## ทำไมถึงร้ายแรง

- **ข้อมูลที่รั่วคือคำถามดูดวง** — ตรงตามหมวดข้อมูลอ่อนไหวที่ PDPA คุ้มครอง (สุขภาพ ความสัมพันธ์ การเงิน)
- ความลับอยู่ใน **query string** จึงไปโผล่ใน access log ของ CDN/proxy, `Referer` header และประวัติเบราว์เซอร์
- `GET /api/marketplace/tickets/<id>` ต้องการแค่ ticket id ซึ่งอยู่ในลิงก์ `/readers/queue/<id>` ที่ผู้ใช้แชร์ต่อได้

## แก้ไปแล้วบางส่วน (PR #234)

✅ การ **ยกเลิก** ตั๋วบังคับ `customerRef` แล้ว (เดิมใช้แค่ ticket id — ใครเห็นลิงก์ก็เตะลูกค้าออกจากคิวได้)
✅ การเปิดรายการชำระเงินบังคับ `customerRef` แล้ว
❌ การ **อ่าน** ยังเปิดอยู่ทั้งสองปลายทาง

## เป้าหมาย

ย้าย `customerRef` จาก query string ไปเป็น **cookie httpOnly ที่เซ็นลายเซ็น** โดยใช้ของที่มีอยู่แล้วใน [`src/lib/auth/edge-auth.ts`](../../src/lib/auth/edge-auth.ts):

```ts
export async function signPayload(payload: Record<string, unknown>): Promise<string>   // :63
export async function verifyPayload<T>(token: string): Promise<T | null>               // :80
```

## ขั้นตอนละเอียด

### 1.1 สร้างตัวช่วยกลาง — ไฟล์ใหม่ `src/lib/marketplace/customer-ref.ts`

```ts
import { cookies } from "next/headers";
import { signPayload, verifyPayload } from "@/lib/auth/edge-auth";

export const CUSTOMER_REF_COOKIE = "tarot_customer_ref";
const MAX_AGE_SEC = 60 * 60 * 24 * 30; // 30 วัน — คิวมีอายุสั้นกว่านี้มาก

/**
 * ⚠️ `customerRef` คือความลับแบบ bearer (ใครถือ = เป็นเจ้าของตั๋ว)
 * ห้ามรับผ่าน query string หรือ body เพื่อ "อ่าน" ข้อมูลเด็ดขาด — ต้องมาจาก cookie ที่เราเซ็นเองเท่านั้น
 * เหตุผล: คำถามดูดวงเป็นข้อมูลอ่อนไหวตาม PDPA · ค่าใน URL รั่วผ่าน access log / Referer / ประวัติเบราว์เซอร์
 */
export async function readCustomerRefFromCookie(): Promise<string | null> {
  const token = (await cookies()).get(CUSTOMER_REF_COOKIE)?.value;
  if (!token) return null;
  const payload = await verifyPayload<{ ref?: string }>(token);
  return typeof payload?.ref === "string" && payload.ref.length >= 6 ? payload.ref : null;
}

/** ปั๊ม cookie ให้ response — เรียกตอนสร้างตั๋วสำเร็จเท่านั้น */
export async function attachCustomerRefCookie(res: Response, ref: string): Promise<Response> {
  const token = await signPayload({ ref });
  res.headers.append(
    "Set-Cookie",
    `${CUSTOMER_REF_COOKIE}=${token}; Path=/; HttpOnly; SameSite=Lax; Max-Age=${MAX_AGE_SEC}` +
      (process.env.NODE_ENV === "production" ? "; Secure" : "")
  );
  return res;
}
```

> 💡 ดูรูปแบบการตั้ง cookie ที่โปรเจกต์ใช้อยู่ได้ที่ `authCookieOptions()` ใน `src/lib/auth/session.ts:24-32` ให้ตั้งค่าให้สอดคล้องกัน

# 🟠 2. ISSUE-017 · โควตาเปิดไพ่ถูกใช้ซ้อนได้ถ้ายิงขนาน (double-spend)

## อาการที่ทำซ้ำได้

สมาชิกที่เหลือโควตา 1 ครั้ง:

```bash
# 1) ขอ reading id สามใบ
for i in 1 2 3; do curl -s -X POST https://<host>/api/reading/start -H 'Cookie: <session>' -d '...'; done
# 2) ยิงอ่านพร้อมกันทั้งสาม
curl ... /api/reading/A/read & curl ... /api/reading/B/read & curl ... /api/reading/C/read & wait
```

→ ผ่านทั้งสาม ใช้ AI 3 รอบ แต่หักโควตาแค่ 1

## ต้นเหตุ

`src/lib/entitlement/entitlement.ts:296-326` เป็น **read-check-then-insert ที่ไม่มี transaction**:

```ts
const already = await db.prepare(`SELECT 1 AS x FROM reading_usage WHERE reading_id = ? LIMIT 1`)...
if (already) return true;

ent = await getEntitlement(v);                       // ← อ่านยอดคงเหลือ
if (!ent.canStartReading && ent.remaining <= 0) return false;

const source = ent.dailyRemaining > 0 ? "daily" : "bonus";
await db.prepare(`INSERT INTO reading_usage (...) VALUES (?, ?, ?, ?, ?, ?)`)...   // ← เขียนทีหลัง
```

- `UNIQUE(reading_id)` (migration `0007`) กันได้แค่การหักซ้ำของ **reading เดียวกัน** — คนละ reading ไม่ชนกัน
- `maxConcurrent` ใน `src/lib/utils/rate-limit.ts` เก็บ state ใน `Map` ระดับโมดูล → คนละ Worker isolate เห็น `concurrent = 0` เหมือนกันหมด กันไม่ได้

## แนวทางแก้ที่แนะนำ — ทำให้ INSERT จำกัดตัวเอง

ให้เงื่อนไขโควตาอยู่ **ในคำสั่ง INSERT เดียวกัน** แล้วอ่าน `meta.changes` เป็นคำตอบ

```ts
const now = Date.now();
const dk = todayDateKey();
const wk = weekKey();

// ── ชั้นที่ 1: โควตารายวัน ───────────────────────────────────────────
// เงื่อนไขนับต้องตรงกับ memberUsage() เป๊ะ ๆ (ดูคอมเมนต์ที่นั่นเรื่องวันจันทร์ — INC-0074)
const daily = await db
  .prepare(
    `INSERT INTO reading_usage (id, user_id, reading_id, week_key, source, consumed_at)
     SELECT ?, ?, ?, ?, 'daily', ?
      WHERE (
        SELECT COUNT(*) FROM reading_usage
         WHERE user_id = ?
           AND ((source = 'weekly' AND week_key = ?)
             OR (source NOT IN ('weekly', 'bonus') AND week_key = ?))
      ) < ?`
  )
  .bind(`ru_${crypto.randomUUID()}`, v.userId, readingId, dk, now, v.userId, wk, dk, DAILY_LIMIT)
  .run();

if ((daily.meta?.changes ?? 0) > 0) return true;

// ── ชั้นที่ 2: โควตาโบนัส/ที่ซื้อมา ────────────────────────────────
const bonus = await db
  .prepare(
    `INSERT INTO reading_usage (id, user_id, reading_id, week_key, source, consumed_at)
     SELECT ?, ?, ?, ?, 'bonus', ?
      WHERE (SELECT COALESCE(SUM(granted), 0) FROM user_bonus WHERE user_id = ?)
          > (SELECT COUNT(*) FROM reading_usage WHERE user_id = ? AND source = 'bonus')`
  )
  .bind(`ru_${crypto.randomUUID()}`, v.userId, readingId, dk, now, v.userId, v.userId)
  .run();

return (bonus.meta?.changes ?? 0) > 0;
```

### สิ่งที่ต้องคงไว้ให้ครบ

- ✅ fast path `SELECT 1 ... WHERE reading_id = ?` ยังต้องอยู่ (กันกดรัว/รีทรายของ reading เดิม)
- ✅ `catch (isUniqueViolation) → return true` ยังต้องอยู่ (ชน `UNIQUE(reading_id)`)
- ✅ `isMissingTable → trySelfHeal()` ยังต้องอยู่
- ✅ `onDbFailure()` ตาม `DB_FAILURE_POLICY` ยังต้องอยู่ (กฎถาวรจาก INC ก่อนหน้า — ห้ามให้พฤติกรรมตอนระบบล่มเป็นผลพลอยได้ของ try/catch)

### ⚠️ ข้อควรระวังใหญ่

1. **`meta.changes` ต้องเชื่อถือได้ทั้งสองฝั่ง** — D1 จริงกับ shim `node:sqlite` ใน `src/lib/platform/db.ts` ต้องคืนค่าตรงกัน **ตรวจข้อนี้ก่อนเริ่มเขียน** ไม่งั้นเทสต์ผ่านแต่ production พัง (หรือกลับกัน)
2. **`recordDailyReading()` สำหรับผัง `daily`** อยู่ก่อนหน้าโค้ดส่วนนี้ — อย่าย้ายลำดับ

ทั้งสองที่ `clearInterval` ตอน unmount ถูกต้องแล้ว **แต่ไม่ได้ดู `document.visibilityState`** — แท็บที่เปิดค้างไว้เบื้องหลังยิง D1 ทั้งวัน

## วิธีแก้

สร้าง hook กลาง `src/lib/utils/use-visible-interval.ts`:

```ts
import { useEffect, useRef } from "react";

/**
 * เรียก `callback` เป็นรอบ ๆ **เฉพาะตอนที่แท็บถูกมองเห็นอยู่เท่านั้น**
 * แท็บที่ถูกซ่อนไม่ควรยิงคำขอต่อ — เปลืองโควตา D1 โดยที่ไม่มีใครดูผลลัพธ์
 * และยิงทันที 1 ครั้งตอนผู้ใช้กลับมาที่แท็บ เพื่อให้ข้อมูลสดทันทีที่เห็นหน้าจอ
 */
export function useVisibleInterval(callback: () => void, ms: number) {
  const cbRef = useRef(callback);
  cbRef.current = callback;

  useEffect(() => {
    let timer: number | null = null;

    const stop = () => {
      if (timer !== null) window.clearInterval(timer);
      timer = null;
    };

    const start = () => {
      stop();
      cbRef.current();
      timer = window.setInterval(() => cbRef.current(), ms);
    };

    const onVisibility = () => (document.visibilityState === "visible" ? start() : stop());

    onVisibility();
    document.addEventListener("visibilitychange", onVisibility);
    return () => {
      document.removeEventListener("visibilitychange", onVisibility);
      stop();
    };
  }, [ms]);
}
```

แล้วแทนที่ `useEffect` + `setInterval` ทั้งสองจุด

> 💡 **บทเรียนจาก #234**: `callback` ต้องเก็บลง ref และ dependency มีแค่ `[ms]` — ถ้าใส่ `callback` ใน deps ทั้งที่ผู้เรียกสร้างใหม่ทุกเรนเดอร์ interval จะถูกรีสตาร์ททุกรอบ (อาการเดียวกับ `Modal` ที่ทำให้หน้าเว็บเลื่อนไม่ได้ถาวร)
