# 🟠 P1 — หนี้ a11y ที่กระจายทั้งเว็บ (ยังเปิดอยู่ทั้งหมด)

> ตรวจซ้ำกับ `main` ล่าสุด (`df87035`) เมื่อ 2026-09-12 — **ทุกข้อในหมวดนี้ยังไม่ถูกแตะเลย**

## UX-04 · ไม่มี skip link สักหน้าเดียว (0 จาก 7 หน้าที่ตรวจ)

`SiteHeader` มีลิงก์เมนู 8 รายการ + สลับภาษา + เข้าสู่ระบบ
ผู้ใช้คีย์บอร์ดและ screen reader ต้อง **กด Tab ผ่าน 11 จุดทุกครั้งที่เปลี่ยนหน้า** ก่อนจะถึงเนื้อหา

**สิ่งที่ต้องทำ**: เพิ่มลิงก์ข้ามใน `RootHtml.tsx` ให้เป็น element แรกใน `<body>`

```tsx
<a href="#main-content" className="sr-only focus:not-sr-only focus:fixed focus:top-3 focus:left-3 focus:z-[200] focus:rounded-lg focus:bg-[#FFFFFF] focus:px-4 focus:py-3 focus:text-ink focus:shadow-overlay">
  {isEnglish ? "Skip to main content" : "ข้ามไปยังเนื้อหาหลัก"}
</a>
```
แล้วเติม `id="main-content"` ให้ `<main>` ทุกหน้า (มี 49 `page.tsx` — แนะนำทำเป็น component `<PageMain>` ครั้งเดียว แทนที่จะไล่แปะทีละหน้า)

> ⚠️ `scroll-padding-top` ของหน้าตั้งไว้ที่ `calc(var(--site-header-h) + 12px)` แล้ว — anchor จะไม่จอดใต้หัวเว็บ ไม่ต้องแก้เพิ่ม

**เกณฑ์รับงาน**: กด Tab ครั้งแรกหลังโหลดหน้า ต้องเห็นลิงก์นี้โผล่ · กด Enter แล้วโฟกัสไปอยู่ที่ `<main>` จริง (ไม่ใช่แค่เลื่อนหน้า) · ทดสอบครบทั้ง 7 หน้าหลัก

## UX-05 · เมนูหลักและ footer ไม่ใช่ landmark `navigation`

- [`SiteHeader.tsx:91`](../../src/components/layout/SiteHeader.tsx#L91) ใช้ `<header>` เปล่า ไม่มี `<nav>` ข้างใน
- แผงเมนูใน `SacredNavDropdown` ประกาศเป็น `role="region"` ไม่ใช่ `navigation`
- [`SiteFooter.tsx:28`](../../src/components/layout/SiteFooter.tsx#L28) ลิงก์ 3 คอลัมน์ ไม่มี `<nav>`

วัดจริง: หน้า `/`, `/cards`, `/blog`, `/cards/major-00` มี `<nav>` = **0 อัน**
(หน้า `/daily`, `/spreads`, `/love/1-card` มี 1 อัน แต่นั่นคือ breadcrumb ไม่ใช่เมนูหลัก)

**สิ่งที่ต้องทำ**
1. ห่อรายการลิงก์ใน `SacredNavDropdown` ด้วย `<nav aria-label="เมนูหลัก">` แทน `role="region"`
2. ห่อลิงก์แต่ละคอลัมน์ใน `SiteFooter` ด้วย `<nav aria-label="…">` (ตั้งชื่อไม่ซ้ำกัน)
3. ใช้ `<ul>/<li>` ให้ screen reader อ่านจำนวนรายการได้

**เกณฑ์รับงาน**: ทุกหน้ามี `navigation` landmark ≥ 1 · ทุก `nav` มีชื่อกำกับและไม่ซ้ำกัน

## UX-06 · จุดบอกตำแหน่งสไลด์ขนาด 6 × 6 px — ตกเกณฑ์ WCAG 2.2 แบบไม่ต้องเถียง

วัดขนาดจริงบน production (viewport 375 px):

| องค์ประกอบ | ขนาดจริง | WCAG 2.2 SC 2.5.8 ต้องการ |
|---|---|---|
| จุดสไลด์หัวข้อดูดวง × 4 | **6 × 6 px** (จุดที่ active = 24 × 6) | ≥ 24 × 24 |
| จุดสไลด์เลือกผัง × 5 | **6 × 6 px** (active = 28 × 6) | ≥ 24 × 24 |

จุดพวกนี้เป็น `<button>` จริงและมี `aria-label` ครบ (ทำได้ดีแล้ว) — ปัญหาอยู่ที่ **นิ้วกดไม่โดน** เท่านั้น

**ต้นเหตุ**: [`QuickFortunePicker.tsx:384`](../../src/components/reading/QuickFortunePicker.tsx#L384) · [`SpreadCardSelector.tsx:368`](../../src/components/spread/SpreadCardSelector.tsx#L368) · [`PersonaCardSelector.tsx:279`](../../src/components/reading/PersonaCardSelector.tsx#L279) ทั้งสามใช้แพตเทิร์น `h-1.5 rounded-full` เหมือนกัน

**สิ่งที่ต้องทำ**: ห่อจุดด้วยปุ่มโปร่งใสขนาด 24×24 โดย **ไม่เปลี่ยนหน้าตาที่ตาเห็นแม้แต่พิกเซลเดียว**

```tsx
<button aria-label={...} className="grid place-items-center h-6 w-6 -m-1 focus-visible:outline-none">
  <span aria-hidden className="h-1.5 rounded-full …" />
</button>
```
`-m-1` ดึงระยะกลับ ทำให้ layout เดิมไม่ขยับ

**เกณฑ์รับงาน**: ทุกจุดวัดได้ ≥ 24 × 24 · ภาพหน้าจอก่อน/หลังต้องเหมือนกันทุกพิกเซล · เพิ่มด่าน CI กันแพตเทิร์น `h-1.5 rounded-full` บน element ที่คลิกได้

## UX-07 · ไม่มีพื้นที่กดขั้นต่ำ 44 px เลยทั้งโค้ดเบส

วัดบนหน้าแรกอย่างเดียว: **44 องค์ประกอบที่กดได้มีด้านใดด้านหนึ่งเล็กกว่า 44 px**
สแกนทั้ง repo: `min-h-[44px]` / `min-w-[44px]` / `min-h-11` = **0 จุด**

ตัวอย่างที่วัดได้จริง:

| ปุ่ม | ขนาดจริง |
|---|---|
| ปุ่มเมนูหลัก (แฮมเบอร์เกอร์) | 36 × 36 |
| ปุ่มเข้าสู่ระบบ | 36 × 36 |
| ปุ่มสลับภาษา ไทย / EN | 31 × 37 และ 31 × 34 |
| ปุ่ม `ยินยอม` / `เฉพาะที่จำเป็น` ใน consent banner | สูง 38 และ 40 |
| ลิงก์ `ดูผังทั้งหมด` · `คลังไพ่ 78 ใบ` | สูง 21 |

และจากการสแกนโค้ด พบปุ่มที่เสี่ยงอีก **28 จุด** กระจาย 22 ไฟล์ (`py-1` · `py-1.5` · `p-1` · `h-9 w-9`)
รายชื่อเต็มอยู่ในภาคผนวก A

**สิ่งที่ต้องทำ**
1. เพิ่ม utility กลางใน `globals.css`:
   ```css
   .tap-target { min-height: 44px; min-width: 44px; }
   ```
2. ไล่ใส่ตามลำดับความสำคัญ: หัวเว็บ → consent banner → ปุ่มในพิธีกรรมเปิดไพ่ → ที่เหลือ
3. ใส่ด่าน CI ที่ fail ถ้ามี `<button>` ใหม่ที่ padding แนวตั้ง ≤ `py-2` โดยไม่มี `tap-target` / `min-h-*`

> 💡 **ข้อควรระวังเรื่องดีไซน์**: เว็บนี้เป็น Editorial Quiet Luxury — การขยายปุ่มให้ใหญ่ขึ้นตรง ๆ จะทำให้หัวเว็บดูเทอะทะ
> ให้ขยาย **พื้นที่กด** ด้วย padding + margin ลบ (แบบเดียวกับ UX-06) แทนการขยาย **พื้นที่ที่ตาเห็น**

**เกณฑ์รับงาน**: องค์ประกอบที่กดได้บนหน้าแรก < 44 px เหลือ ≤ 5 จุด (ยกเว้นลิงก์ในเนื้อความที่เป็น inline text ได้) · หน้าตาไม่เปลี่ยน

## UX-09 · `Field.tsx` วาง `aria-describedby` ผิดที่ → คำอธิบายและข้อความ error ไม่เคยถูกอ่านออกมาเลย

[`Field.tsx:25`](../../src/components/ui/Field.tsx#L25):

```tsx
<div aria-describedby={describedBy}>{children(id)}</div>
```

`aria-describedby` ต้องอยู่บน **ตัว control** ไม่ใช่ `<div>` ที่ห่อมันอยู่
ผลคือ hint และ error ที่อุตส่าห์เขียน `id` ผูกไว้เรียบร้อย **ไม่เคยถูก screen reader อ่านสักครั้ง**

และทั้งโค้ดเบส **ไม่มี `aria-invalid` แม้แต่จุดเดียว** — ผู้ใช้ screen reader ไม่มีทางรู้ว่าช่องไหนกรอกผิด

**สิ่งที่ต้องทำ**: เปลี่ยน signature ให้ส่งทั้ง `id` และ `aria` props ลงไปที่ control โดยตรง

```tsx
children: (props: { id: string; "aria-describedby"?: string; "aria-invalid"?: boolean }) => React.ReactNode
```
แล้วไล่แก้ที่เรียกใช้ทุกจุด

**เกณฑ์รับงาน**: VoiceOver / NVDA อ่าน label + hint + error ครบทั้งสามส่วนเมื่อโฟกัสเข้าช่อง · ช่องที่ผิดประกาศ `aria-invalid="true"`

## UX-18 · 49 เส้นทาง ไม่มี `loading.tsx` สักไฟล์เดียว

```
find src/app -name "loading.tsx"   →  0 ไฟล์
find src/app -name "error.tsx"     →  1 ไฟล์  (src/app/(th)/error.tsx)
find src/app -name "not-found.tsx" →  3 ไฟล์
```

ผลที่ตามมา:
1. **เปลี่ยนหน้าแล้วจอค้างเฉย ๆ** ไม่มีอะไรบอกว่าระบบกำลังทำงาน — Next.js App Router จะรอ server component เสร็จก่อนวาด และไม่มี fallback ให้แสดง
2. **กลุ่มเส้นทาง `(en)` ไม่มี `error.tsx` เลย** → ถ้าหน้าอังกฤษพัง ผู้ใช้เจอจอขาวหรือ error ดิบ ๆ จาก `global-error` แทนที่จะเป็นหน้าที่ออกแบบไว้
3. มี `animate-pulse` แค่ 16 จุดทั้งเว็บ — โครงกระดูกโหลดมีน้อยมากเมื่อเทียบกับจำนวนหน้า

**สิ่งที่ต้องทำ**
1. สร้าง `loading.tsx` ให้กลุ่มหลักก่อน: `(th)/cards` · `(th)/blog` · `(th)/spreads` · `(th)/readers` และคู่ EN
   ใช้โครงกระดูกที่ **หน้าตาตรงกับเนื้อหาจริง** (กริดไพ่ = กริดสี่เหลี่ยมสัดส่วน 300:520) ไม่ใช่สปินเนอร์กลางจอ
2. คัดลอก `(th)/error.tsx` ไปเป็น `(en)/error.tsx` พร้อมแปลข้อความ
3. ทุกโครงกระดูกต้องมี `aria-busy="true"` + `aria-label` บอกว่ากำลังโหลดอะไร

> ⚠️ `globals.css` เตือนไว้แล้วว่าห้ามใช้ `animation: none !important` ใน `prefers-reduced-motion`
> เพราะจะฆ่าแอนิเมชันที่สื่อ "สถานะกำลังทำงาน" — โครงกระดูกใหม่ต้องยังเห็นว่าเคลื่อนไหวอยู่ (แค่สั้นลง)

## UX-19 · แถบขอความยินยอมทับหน้าต่างทุกบาน และเป็นจุด Tab แรกทั้งที่อยู่ล่างจอ

[`ConsentBanner.tsx:42`](../../src/components/analytics/ConsentBanner.tsx#L42):
```
fixed bottom-3 left-3 right-3 … z-100
```

**ผังชั้นความสูงของเว็บนี้**: `z-100` (consent) > `z-60` (2 จุด) > `z-50` (หัวเว็บ · **ทุกโมดัล** · toast) > `z-40` > `z-30` (ปุ่ม TikTok ลอย)

ปัญหา 4 ข้อที่เกิดตามมา:
1. **แถบยินยอมลอยทับ `AuthModal` และโมดัลอื่นทุกบาน** (ทั้งหมดอยู่ที่ `z-50`)
2. บนมือถือมันกินความกว้างเต็มจอที่ขอบล่าง → **ทับปุ่ม CTA ท้ายหน้าจนกว่าจะกดปิด**
3. อยู่**ต้น DOM แต่ล่างสุดของจอ** → กด Tab ครั้งแรกโฟกัสกระโดดลงล่างสุด ทั้งที่ตายังมองอยู่ข้างบน
4. **ทับพื้นที่ปุ่ม TikTok ลอย** (`bottom-5 right-5`) บนมือถือ
5. ประกาศเป็น `role="region"` ไม่ใช่ `dialog` และไม่กักโฟกัส — ทั้งที่พฤติกรรมมันคือหน้าต่างขวางทาง

**สิ่งที่ต้องทำ**
1. ทำ **z-index scale กลาง** ใน `globals.css` แล้วบังคับใช้ — เสนอ: `base 0 · content 1 · sticky 20 · header 50 · dropdown 60 · modal 80 · toast 90 · consent 70`
   (consent ต้อง **ต่ำกว่า modal**)
2. เลื่อนตำแหน่งแถบยินยอมให้ไม่ทับปุ่ม TikTok บนมือถือ
3. ให้โฟกัสวิ่งเข้าแถบยินยอมตอนโผล่ และคืนกลับตอนปิด · เพิ่ม Esc = "เฉพาะที่จำเป็น"

## UX-20 · พัดไพ่ 78 ใบ = 78 จุด Tab

[`InteractiveCardFan.tsx:48-49`](../../src/components/deck/InteractiveCardFan.tsx#L48) ให้ `tabIndex={0}` กับไพ่**ทุกใบ**
ผู้ใช้คีย์บอร์ดต้องกด Tab **78 ครั้ง** เพื่อผ่านสำรับ และไม่มีทางลัดใด ๆ

ส่วนที่ทำถูกแล้ว: `role="button"` + `aria-label` + `aria-disabled` + รองรับ Enter/Space ครบ ✅

**สิ่งที่ต้องทำ**
1. ใช้ **roving tabindex** — ไพ่ที่ active ได้ `0` ที่เหลือ `-1` แล้วให้ลูกศรซ้าย/ขวาเลื่อน (แพตเทิร์นเดียวกับแท็บที่หน้าแรกทำถูกอยู่แล้ว)
2. เพิ่มปุ่ม `หยิบไพ่ให้ฉันหนึ่งใบ` ที่เข้าถึงได้จากคีย์บอร์ดในหนึ่งจังหวะ
   — ข้อนี้ช่วย **ผู้ใช้มือถือทั่วไปด้วย** ไม่ใช่แค่ผู้ใช้คีย์บอร์ด
3. เปลี่ยน `role="button"` เป็น `<button>` จริง (มี 7 ไฟล์ที่ใช้แพตเทิร์นนี้ — ทุกไฟล์มี `onKeyDown` ครบแล้ว แต่ `<button>` ได้ของฟรีมากกว่า)

> 💡 **ข้อสังเกตเรื่องนิ้ว**: ไพ่กว้าง 46 px บนมือถือ แต่**ซ้อนทับกันเป็นพัด** พื้นที่กดจริงต่อใบจึงแคบกว่านั้นมาก
> ควรวัดพื้นที่กดจริงหลังหักส่วนที่ถูกทับ แล้วเทียบกับ UX-07 ด้วย
