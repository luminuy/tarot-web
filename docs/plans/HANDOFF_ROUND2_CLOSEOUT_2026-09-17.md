## 1 · ข้อ 9 — ธงสิทธิ์บน production (ปิดแล้ว)

ผลตรวจถามว่า "`entitlement.enforced` ถูกตั้งเป็น `false` ไว้หรือเปล่า" และสรุปเองว่า
**ตัดสินจากโค้ดไม่ได้** เพราะค่าเริ่มต้นใน [`src/lib/entitlement/flag.ts`](../../src/lib/entitlement/flag.ts)
คือ "เปิด" · คำตอบเดิมคือ "ให้เจ้าของเปิด `/admin` อ่านเอง"

รอบนี้อ่านค่าจริงจาก KV ของ production ตรง ๆ (สิทธิ์ `wrangler` ที่มีอยู่แล้วบนเครื่อง):

```
app:flag:entitlement.enforced  ➔  {"value":true}
```

**แปลว่าระบบสิทธิ์ถูกบังคับใช้อยู่จริงบน production** — ไม่มีใครปิดไว้ · ไม่ใช่บั๊ก · ไม่ต้องแก้อะไร

และเพื่อไม่ให้คำถามนี้ต้องรบกวนคนที่ล็อกอินแอดมินได้อีก รอบนี้เพิ่ม
[`scripts/flags-show.ts`](../../scripts/flags-show.ts) (`npm run flags:show`) ที่:

- อ่าน namespace id จาก `wrangler.jsonc` เสมอ (ย้าย namespace เมื่อไหร่ก็ตามไปเอง)
- แปลค่าดิบทั้งสองรูปที่โค้ดรองรับ (`false` และ `{ "value": false }`) เป็นคำตอบเดียว
- **อ่านอย่างเดียว** ไม่มีคำสั่งเขียนในไฟล์เลย — แก้ค่าธงยังทำได้ที่ `/admin` ที่เดียวเหมือนเดิม

## 2 · R-26 — ยุบสถานะที่เหลือของ `TarotFlow` (ปิดแล้ว)

"กฎเหล็กข้อ 4 กับข้อ 14 คุ้มครองอยู่ ยุบผิดแปลว่าไพ่แสดงผลผิด ซึ่ง typecheck อย่างเดียวพิสูจน์ไม่พอ"
รอบนี้ยุบครบทั้งสามกลุ่มพร้อมชุดทดสอบตัวลดแบบเดียวกับ `test-flow-overlay.ts`

| ไฟล์ใหม่ | ยุบอะไร | สถานะที่ "เขียนออกมาไม่ได้อีกแล้ว" |
| :--- | :--- | :--- |
| [`flow-deck.ts`](../../src/components/home/flow-deck.ts) | `pickedIndices` · `drawnCards` · `revealedOrders` · `activeCardIndex` | จั่วไพ่ชุดใหม่แล้วไพ่ยังหงายค้าง (**กฎเหล็กข้อ 4**) · พลิก/เพ่งไพ่ที่ไม่มีอยู่ในสำรับ (**กฎเหล็กข้อ 14**) · จับไพ่เกินจำนวนที่ผังต้องการ |
| [`flow-session.ts`](../../src/components/home/flow-session.ts) | `readingId` · `sessionToken` · `commitment` · `clientSeed` · `proof` | โทเคนเซสชันถูกทับด้วยค่าว่าง · หลักฐาน provably-fair ของรอบที่ทิ้งแล้วไหลเข้ารอบใหม่ · เมล็ดฝั่งผู้ใช้หายจนเซิร์ฟเวอร์ต้องสุ่มแทน |

**ตัวเลข**: `useState` ใน `TarotFlow.tsx` **28 ➔ 16** (จากจุดตั้งต้นของผลตรวจ 37 = **ลดลง 57%**)
ratchet ใน `test-flow-overlay.ts` ถูกขันตามเหลือ 16 ทันที

### บั๊กที่การยุบรอบนี้ปิดไปด้วย (ไม่ใช่แค่จัดระเบียบ)

1. **โทเคนถูกทับด้วยค่าว่าง** — โทเคนหมุนใหม่ทุกครั้งที่ยิง `/shuffle` ของเดิมจึงต้องเขียน
   `if (data.sessionToken) setSessionToken(...)` ซ้ำ **4 จุด** · ลืมจุดเดียว = คำขอถัดไปถูกปฏิเสธ
   ตอนนี้กฎ "ค่าว่างไม่ทับของเดิม" อยู่ในตัวลดจุดเดียว
2. **หลักฐานของรอบเก่าไหลเข้ารอบใหม่** — ผู้ใช้กด "เริ่มดูดวงใหม่" ระหว่างสตรีมเก่ายังวิ่ง
   เฟรม `done` ที่มาถึงทีหลังพก `proof` ของไพ่ชุดเดิมมาด้วย ของเดิมรับทันที
   ตอนนี้ `proven` ถูกทิ้งเสมอถ้าไม่มีเซสชันอยู่
3. **ไพ่ชุดใหม่หงายค้าง** — ของเดิมต้องจำไปเรียก `setRevealedOrders([])` ให้ครบทุกจุดที่จั่วไพ่ (มีสองจุด)
   ตอนนี้ `deal` คว่ำไพ่ให้เองเสมอ

## 3 · R-31 — โค้ดตายและรายงาน `knip` ที่ผิด (ปิดแล้ว)

### 3.1 ต้นตอของ "รายงานผิด 10 จุด" ถูกแก้ที่คอนฟิก ไม่ใช่ที่ความจำของคน

ผลตรวจเตือนเองว่า `knip` รายงานผิดเพราะ**ไม่ได้นับ `scripts/**` เป็นจุดเริ่ม** — ของที่ด่าน CI
ใช้จริง (`CARD_IMAGE_VARIANTS` · `boxOf` · `MAP_MIN_COLUMN_PX` · `generateClientSeed`)
จึงถูกฟ้องว่าไม่มีใครใช้ · ลบตามรายงานเมื่อไหร่ ด่านพังทันที

รอบนี้ commit [`knip.jsonc`](../../knip.jsonc) ที่มี `scripts/**` · `astro/**` เป็น entry
พร้อมคำเตือนในไฟล์ว่าห้ามถอดออก · รันซ้ำด้วย `npm run deadcode` แล้ว
**ทั้งสี่ตัวนั้นหายจากรายงานทันที** — ปัญหานี้จะไม่กลับมาหลอกรอบตรวจถัดไปอีก

> ⚠️ ไม่ได้ผูก `knip` เข้า `repo:verify` เพราะมันต้องดึงแพ็กเกจจากเครือข่ายตอนรัน
> ซึ่งขัดกับด่านห่วงโซ่อุปทานของ CI (ห้าม import ของที่ไม่ได้ประกาศใน `package.json`)

### 3.2 ของตายจริงที่ลบไปรอบนี้

| ลบอะไร | ทำไมปลอดภัย |
| :--- | :--- |
| `export default` ที่ไม่มีใครนำเข้า 4 จุด (`CardImage` · `RouteLink` · `ConsentBanner` · `AntiTheftShield`) | ทุกจุดในเว็บนำเข้าด้วยชื่อ (named import) ทั้งหมด · การมีสองทางเข้าไปหาของชิ้นเดียวคือกับดักของคนถัดไป |
| `WEEKLY_LIMIT` ใน `limits.ts` + การ re-export ที่ `entitlement.ts` | คอมเมนต์เขียนไว้เองว่า "compatibility alias — โค้ดเก่าบางจุดยังเรียกชื่อนี้" · ตรวจแล้ว **ไม่เหลือจุดไหนเรียกเลย** |
| `export` ของตัวช่วยภายใน 6 ตัว (`b64u` · `unb64u` · `timingSafeEqualBytes` · `getSessionSecret` · `getAuthSecret`) | เป็นชิ้นส่วนภายในของโมดูลรหัสผ่าน/โทเคน · **การไม่ export ตัวอ่านความลับออกนอกไฟล์คือการแคบพื้นที่ผิดพลาดให้แคบลง** ไม่ใช่แค่ความสะอาด |

### 3.3 ของที่ `knip` ฟ้องแล้ว "ยังไม่ลบ" — พร้อมเหตุผลรายกลุ่ม

รายงานหลังใส่คอนฟิกเหลือ **ค่า/ฟังก์ชัน 121 จุด** (type/interface ที่ใช้ในไฟล์ตัวเองถูกกรองออก
เพราะเป็นการตั้งชื่อรูปข้อมูลให้คนอ่านเข้าใจ ไม่ใช่ API ที่ลืมเก็บ) · ไล่ดูแล้วแบ่งได้ 4 กลุ่ม:

| กลุ่ม | ตัวอย่าง | ทำไมยังอยู่ |
| :--- | :--- | :--- |
| **โครงสร้างพื้นฐานที่รอเฟสถัดไป** | `payments.repo` · `queue.repo` · `embedTexts` · `apiOk`/`apiFail` | เขียนไว้ตามแผนที่ยังไม่เปิด (Marketplace · ค้นหาเชิงความหมาย · ซองจดหมายรูปใหม่ที่ route ยังทยอยย้าย) — ลบทิ้งคือการลบแผน |
| **คู่ภาษาอังกฤษของข้อมูลไทย** | `MEMBER_BENEFITS_EN` · `ACCESS_PLANS_EN` · `CREDIT_PACKAGES_EN` · `HOME_FAQS_EN` | คู่ไทยถูกใช้อยู่ · คู่อังกฤษรอหน้าที่ยังไม่เปิด — ลบแล้วเปิดหน้าอังกฤษรอบหน้าต้องเขียนใหม่ทั้งชุด |
| **ของที่ผูกกับกฎความปลอดภัย/ความถูกต้อง** | `CRISIS_RULES_TH` · `CRISIS_RULES_LATIN` · `FOREIGN_SCRIPT_REGEX` · `LATIN_LEAK_MAP` | เป็นตารางกฎที่ถูกใช้ผ่านฟังก์ชันในไฟล์เดียวกัน · แตะเมื่อไม่จำเป็น = ความเสี่ยงโดยไม่มีผลตอบแทน |
| **UI ที่ไม่มีใครเรนเดอร์แล้วจริง ๆ** | `RitualStepProgress` (132 บรรทัด) · `loading-skeletons` 7 ตัว · `MiniRwsCard` | **นี่คือกลุ่มเดียวที่ควรลบจริง** แต่เป็นงานตัดสินใจเรื่องหน้าตาเว็บ ไม่ใช่งานทำความสะอาด — ยกให้เจ้าของเคาะ (ดู ISSUE-049) |

### 3.4 ฮุกกำพร้า — ของตายที่ใหญ่ที่สุดที่เจอในรอบนี้

`knip` รายงาน [`src/lib/admin/use-admin-resource.ts`](../../src/lib/admin/use-admin-resource.ts)
ว่าเป็น **ไฟล์กำพร้าทั้งไฟล์** — ฮุกกลางที่รอบก่อนเขียนขึ้นเพื่อปิด R-28
แต่ **ไม่มีแผงแอดมินไหนเรียกใช้เลยสักแผง** ทุกแผงยังลอกชุด `fetch`/`loading`/`error` ของตัวเองไว้เหมือนเดิม

แย่กว่านั้นคือด่านที่ควรจับเรื่องนี้กลับเขียนไว้ว่า:

```ts
check("มีฮุกโหลดข้อมูลกลางของแผงแอดมิน (use-admin-resource.ts)", fs.existsSync(...));
```

**ด่านที่ตรวจว่า "ไฟล์มีอยู่" คือด่านที่ตกไม่ได้** ตราบใดที่ไม่มีใครลบไฟล์ทิ้ง (บทเรียน INC-0195)

รอบนี้จึงทำสองอย่าง:

1. **ต่อสายจริง 6 แผง** — `AdminOverview` · `AiHealthPanel` · `StatsDashboard` ·
   `SystemHealthPanel` · `EntitlementAdmin` · `MarketingAudience` ใช้ `useAdminResource` หมดแล้ว
   (`StatsDashboard` ถึงขั้นลอกโค้ดในฮุกมาไว้ในตัวเองทั้งก้อนแบบบรรทัดต่อบรรทัด)
2. **เปลี่ยนด่านให้ตรวจการถูกใช้จริง** — นับจำนวนแผงที่เรียกฮุก (ratchet ขั้นต่ำ 6 · เพิ่มได้ ห้ามลด)
   และห้ามแผงไหนยิง `fetch(..., { cache: "no-store" })` โหลดหน้าจอเอง
   ทั้งสองข้อ **ตกแน่นอนถ้ารันกับต้นไม้ก่อนแก้** (ก่อนแก้: แผงที่ใช้ฮุก = 0 · แผงที่ยิงเอง = 6)

### 4.4 R-02 เปลี่ยนรูปยังไง — งานที่ควรทำไม่ใช่งานของ `/spreads`

แยกงานบนเธรดหลัก (รอบที่บล็อกสคริปต์บอตแล้ว = โค้ดเราล้วน):

| หน้า | Style & Layout | Script Evaluation | จำนวน element | งานก้อนยาวที่สุด |
| :--- | ---: | ---: | ---: | :--- |
| `/` | 1,164 ms | 318 ms | 1,005 | 466 ms (เอกสาร) |
| `/cards` | 1,179 ms | 390 ms | 1,722 | 390 ms (เอกสาร) |
| `/blog` | 944 ms | 273 ms | 877 | 367 ms (เอกสาร) |
| `/spreads` | **1,357 ms** | 463 ms | **667** | **687 ms** (`client.js` = hydration) |

อ่านตารางนี้แล้วได้ข้อสรุปที่ต่างจากผลตรวจเดิม:

1. **`/spreads` มี element น้อยที่สุดในสี่หน้า (667) แต่ใช้เวลา Style & Layout มากที่สุด**
   ➔ ต้นทุนนี้ไม่ได้มาจาก "หน้านี้มีของเยอะ" แต่มาจากสไตล์ชีตก้อนเดียวที่ทุกหน้าโหลดเหมือนกัน
   (~0.9–1.4 วินาทีทุกหน้า) ซึ่งก็คือ **R-11/R-12/T-23 เรื่องเดียวกัน**
2. **ส่วนที่เป็นของ `/spreads` เองจริง ๆ คือ hydration** — งานก้อนเดียวยาว 687 ms จาก
   `client.js` และอีก 395 ms จาก island ของหัวเว็บ · หน้านี้ hydrate ทั้งคลังผัง 25 แบบ
   ด้วย `client:idle` เพื่อฟีเจอร์แท็บกรองกับการกดขยาย
3. เพราะฉะนั้น **"ไปไล่ลดโค้ดในหน้า `/spreads`" คือการแก้ผิดที่** — งานจริงมีสองงานคนละเรื่อง:
   ลดต้นทุนสไตล์ชีตทั้งเว็บ (ข้อ 1) และลดขอบเขต hydration ของคลังผัง (ข้อ 2)

**ทำไมรอบนี้ไม่ลงมือแก้ต่อ**: ทั้งสองงานเปลี่ยนโครงหน้าเว็บจริง
(แยกคลังผังเป็นส่วน static + island เล็ก หรือสกัด critical CSS) ซึ่งต้องวัดก่อน-หลังบน production
และผลตรวจเองก็ลด R-02 เป็น **LOW** ไปแล้ว · จึงบันทึกตัวเลขกับทิศทางไว้ให้รอบที่ตั้งใจทำเรื่องนี้โดยเฉพาะ

## 4.5 · ภาคต่อ (รอบเดียวกัน · หลังเจ้าของสั่ง "แก้ข้อ 1-2 เลย")

### R-02 — เลิก hydrate คลังผังทั้งก้อน (ลงมือแล้ว)

จากบทวิเคราะห์ในหัวข้อ 4.4: ครึ่งหนึ่งของต้นทุน `/spreads` คือสไตล์ชีตที่ทุกหน้าจ่ายเท่ากัน
อีกครึ่งคือ **hydration ของคลังผัง 25 แบบ** (งานก้อนเดียวยาว 687 ms) · ครึ่งหลังแก้ได้ในโค้ด จึงแก้

**วิธี**: การ์ดทั้ง 25 ใบเรนเดอร์เป็น HTML ตั้งแต่ตอนบิลด์ (เดิมเรนเดอร์แค่ 6 ใบของแท็บแรก)
แท็บหมวดทำงานด้วยสคริปต์ ~1 KB ([`astro/scripts/spreads-tabs.ts`](../../astro/scripts/spreads-tabs.ts))
ที่แค่สลับแอตทริบิวต์ `hidden` · ปุ่มขยายดูตำแหน่งไพ่เปลี่ยนไปใช้ `<details>` ของเบราว์เซอร์
➔ **ไม่มี React บนหน้านี้แล้วนอกจาก island ของหัวเว็บ/ฟุตเตอร์**

**ผลที่วัดจากบิลด์จริง** (นับไบต์ gzip ของทุกไฟล์ที่หน้านี้อ้างถึง ไม่ใช่ประมาณ):

| | ก่อน | หลัง | ส่วนต่าง |
| :--- | ---: | ---: | ---: |
| JS (gzip) | 124.4 KB | **100.1 KB** | **−24.3 KB** |
| HTML (gzip) | 20.0 KB | 33.8 KB | +13.8 KB |
| **รวมที่ผู้ใช้ต้องโหลด** | 144.4 KB | **133.9 KB** | **−10.5 KB** |
| ลิงก์ผังใน HTML ดิบ | 6 เส้น | **25 เส้น** | +19 |
| ไฟล์ JS ที่ต้องโหลด | 21 ก้อน | 19 ก้อน | −2 |

⚠️ **นี่คือการแลกที่ตั้งใจ ไม่ใช่ของฟรี** — HTML โตขึ้น 13.8 KB เพราะเรนเดอร์ครบ 25 ใบ
แลกกับ JS ที่หายไป 24.3 KB (ข้อมูลผัง 17.2 KB + ตัวคลัง) และงาน hydration ที่หายไปทั้งก้อน
เพดานในด่านงบบันเดิลถูกแก้พร้อมเหตุผลครบทั้งสองฝั่ง (HTML 26 ➔ 38 · **JS 136 ➔ 120 = ขันให้แน่นขึ้น**)

**พิสูจน์ว่ายังใช้งานได้จริง** (ยิงใส่บิลด์ในเครื่องผ่านเบราว์เซอร์จริง):
สลับแท็บได้ครบทั้ง 5 หมวด — แนะนำ 6 · ความรัก 5 · การงาน 5 · ผังใหญ่ 5 · ทั้งหมด 25 ใบ
(ตรงกับตัวเลขบนแท็บทุกตัว) · ลูกศรซ้าย/ขวาเลื่อนแท็บได้ · `aria-labelledby` ของแผงตามแท็บที่เลือก ·
`<details>` ย่อ/ขยายได้จริง (308 ➔ 2,952 px) · ปิด JS ทิ้งก็ยังเห็นแท็บแรกและสารบัญ 25 เส้นครบ

**ผลจริงบน production หลัง deploy** (Lighthouse 13.4.1 · มือถือ · `simulate` · ยิงสองรอบ):
