## 2. ระเบิดเวลา 4 ข้อ — ต้องปิดก่อนเปิดหน้าแอดมิน

### 2.1 🔴 ไม่มีด่านกันเดารหัส — เดาได้ไม่จำกัดครั้ง

`src/app/api/entitlement/redeem/route.ts` ไม่มี rate limit สักชั้น ขอแค่ล็อกอินก็ยิงได้รัว
รวมกับ `max_uses = -1` ของรหัสที่ seed ไว้ ⇒ **รหัสหลุด/เดาเจอ 1 ใบ = แจกสิทธิ์พรีเมียมฟรีไม่จำกัดคน** และไม่มีทางรู้ตัว

**ต้องทำ**: ใส่ `checkAuthRateLimit` จาก `src/lib/security/auth-ratelimit.ts` (ตัวเดียวกับที่ใช้กันเดารหัสผ่าน — มีถังต่อ IP · ต่อ IP+บัญชี · ต่อบัญชี อยู่แล้ว) โดยเพิ่ม action `"redeem"` เข้า `AuthRateLimitAction`
เกณฑ์ที่เสนอ: `ipMax 20` · `pairMax 10` · `idMax 10` · `windowSec 3600`

> อย่าเขียน rate limiter ตัวใหม่เอง — `auth-ratelimit.ts:14-32` มีคอมเมนต์เตือนกับดักที่บ้านนี้เคยเหยียบมาแล้ว 2 ข้อ (หยิบ `x-forwarded-for` ผิด hop · ผสมวันที่ลงในคีย์แล้วถังรีเซ็ตเองตอนเที่ยงคืน)

### 2.2 🔴 แลกแล้วอาจไม่ได้เครดิต และแลกใหม่ไม่ได้ตลอดชีพ

`redeem.ts:113-131` ทำ 3 จังหวะเรียงกันโดยไม่มี transaction:

```
1. INSERT redeem_redemptions   ← กันแลกซ้ำ (UNIQUE)
2. UPDATE used_count + 1
3. grantBonus(...)             ← เขียนเครดิตจริง
```

แต่ `grantBonus` ที่ `entitlement.ts:390-405` **กลืน error ทิ้งทั้งหมด** (`catch { console.error }` แล้ว `return` เฉย ๆ)

⇒ ถ้าจังหวะ 3 ล้ม (D1 throttle / ตาราง `user_bonus` หาย) ผู้ใช้จะ **ถูกตีตราว่าแลกไปแล้ว · `used_count` ถูกกิน · แต่ไม่ได้เครดิตสักหน่วย**
และเพราะ `UNIQUE(code, user_id)` เขาจะแลกรหัสใบนั้น**ไม่ได้อีกตลอดไป** · `route.ts` ยังตอบ `ok: true` ด้วย

**ต้องทำ**: กลับลำดับเป็น `grantBonus` ก่อน แล้วค่อยบันทึก (หรือให้ `redeem.ts` เรียก SQL เขียน `user_bonus` เองแล้วเช็ก `meta.changes`) — อย่างน้อยที่สุดต้องยืนยันว่าเครดิตขึ้นจริงก่อนตอบ `ok: true` และถ้าไม่ขึ้นต้อง rollback แถว `redeem_redemptions`

> D1 มี `db.batch()` ที่รันเป็น transaction เดียวได้ — ใช้ตัวนี้ถ้า local SQLite shim ใน `db.ts` รองรับ (ต้องเช็กก่อน ถ้าไม่รองรับให้ทำ compensating delete แทน แล้วเขียนเหตุผลไว้ในคอมเมนต์)

### 2.3 🟡 `max_uses` กันไม่อยู่จริงเมื่อคนแลกพร้อมกัน

`redeem.ts:93` อ่าน `used_count` มาเทียบ แล้ว `redeem.ts:124` ค่อย `+1` — เป็น check-then-act คนละคำสั่ง
สองคำขอที่มาพร้อมกันจะผ่านด่านทั้งคู่ ⇒ รหัสจำกัด 100 สิทธิ์ถูกแลกเกิน 100 ได้

**ต้องทำ**: ให้ `UPDATE` เป็นตัวตัดสินเอง แล้วอ่าน `meta.changes`

```sql
UPDATE redeem_codes
   SET used_count = used_count + 1
 WHERE code = ?
   AND is_active = 1
   AND (max_uses = -1 OR used_count < max_uses)
   AND (expires_at IS NULL OR expires_at > ?)
```

ถ้า `changes === 0` แปลว่าเต็ม/ปิด/หมดอายุ → ตอบ error และ**อย่า**เขียนเครดิต
ข้อนี้สำคัญขึ้นมากหลังเปิดหน้าแอดมิน เพราะแอดมินจะเริ่มตั้ง `max_uses` เป็นเลขจำกัดจริง ๆ (ตอนนี้ทุกใบเป็น `-1` เลยยังไม่มีใครเจอ)

### 2.4 🟡 ชุดทดสอบ 26 ข้อของระบบนี้ไม่เคยรันใน CI

`scripts/qa/test-redeem-code.ts` มีอยู่จริงและเขียนไว้ดี แต่**ไม่ได้อยู่ใน `CHECKS` ของ `scripts/github-auto.ts:90`**

## 3. สิ่งที่แอดมินต้องทำได้ (ขอบเขตงาน)

| # | ความสามารถ | เหตุผล |
| :-- | :-- | :-- |
| 1 | ดูรายการรหัสทั้งหมด + ยอดแลก `used_count / max_uses` | ตอนนี้ต้องเปิด D1 console ดูเอง |
| 2 | สร้างรหัสใหม่ (พิมพ์เอง หรือกดสุ่มให้) | ตอนนี้ต้องเขียน SQL + deploy |
| 3 | กำหนด **จำนวนสิทธิ์ต่อ 1 การแลก** (`credits`) | เจ้าของสั่งมาตรง ๆ ว่าต้องกำหนดสิทธิ์ได้ |
| 4 | กำหนด **ชนิดสิทธิ์**: พรีเมียม (`purchase_redeem`) หรือ โควตาเปล่า (`promo_redeem`) | ช่องนี้คือตัวตัดสินว่าปลดล็อกผังใหญ่ไหม (ดูข้อ 1) |
| 5 | กำหนด **เพดานจำนวนคนแลก** (`max_uses`, `-1` = ไม่จำกัด) | คุมต้นทุน AI |
| 6 | กำหนด **วันหมดอายุ** (ตามเวลาไทย) | แคมเปญมีอายุ |
| 7 | **เปิด/ปิด** รหัสทันที (`is_active`) | รหัสหลุด = ต้องดับได้ในวินาทีเดียว |
| 8 | ดูว่าใครแลกไปบ้าง (รายการ `redeem_redemptions` ของรหัสนั้น) | ตรวจการโกง |
| 9 | ทุกการกระทำลง audit log | มาตรฐานเดียวกับแท็บอื่นในแผงแอดมิน |

### ❌ สิ่งที่ **ห้าม** ทำในรอบนี้
- **ห้ามมีปุ่มลบรหัส** — `redeem_redemptions.code` เป็น FK ชี้กลับมา ลบแล้วประวัติการแลกกำพร้า ให้ใช้ "ปิดใช้งาน" แทน
- **ห้ามให้แก้ `code` ของรหัสที่มีคนแลกไปแล้ว** — `reason` ใน `user_bonus` ฝังชื่อรหัสเก่าไว้ แก้แล้วสืบกลับไม่ได้
- **ห้ามให้แก้ `credits` ของรหัสที่มีคนแลกไปแล้ว** — คนที่แลกก่อนจะได้ไม่เท่ากับที่หน้าจอบอก ให้สร้างรหัสใบใหม่แทน
- **ห้ามเพิ่มปุ่ม "คืนสิทธิ์/ลบการแลก"** — เกินขอบเขต และแตะ `user_bonus` ตรง ๆ อันตราย
