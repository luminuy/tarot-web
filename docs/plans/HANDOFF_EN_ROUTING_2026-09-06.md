## 1. ปัญหาที่ต้องแก้ให้ตรงจุด

วันนี้ `buildAlternates()` ใน [`src/lib/config/site.ts:97`](../../src/lib/config/site.ts) ประกาศว่า

```html
<link rel="alternate" hreflang="en-US" href="https://seertarot.net/cards?lang=en" />
```

แต่ `/cards?lang=en` **เสิร์ฟ HTML ชุดเดียวกับ `/cards` เป๊ะ ๆ** (หน้า SSG · query ไม่เปลี่ยนผลลัพธ์ตอน build)
และหน้านั้นประกาศ `<link rel="canonical" href="https://seertarot.net/cards">` ทับตัวเองอีกที

> 📝 **แก้คำอธิบายเดิม (2026-09-06)**: ฉบับแรกของแผนนี้เขียนว่า "hreflang ไม่ปรากฏในหน้าใดเลย"
> ซึ่ง **ผิด** — เกิดจากตอนตรวจใช้ `grep hreflang` ตัวพิมพ์เล็ก แต่ Next.js เขียนแอตทริบิวต์ออกมา
> เป็น `hrefLang` (ตัว L ใหญ่) แท็กจึงมีอยู่จริงมาตลอด · ข้อสรุปไม่เปลี่ยน แต่เหตุผลเปลี่ยน:
> ปัญหาไม่ใช่ "ไม่มีแท็ก" แต่คือ **"มีแท็กที่ชี้ไปยัง URL ซึ่งไม่ใช่ฉบับอังกฤษจริง"**

**ผลที่เกิดขึ้นจริงกับ Google** — ไม่ใช่ "โดนลงโทษ" แต่คือ **"ถูกเมิน"**:
กฎของ Google คือปลายทางของ `hreflang` ต้องเป็น URL ที่ canonical ชี้หาตัวเอง
เมื่อ `?lang=en` self-canonical กลับไปหา `/cards` ทั้งคู่ → Google **ทิ้งคำประกาศ hreflang ทั้งชุด**

> 📌 สรุปเป็นประโยคเดียว: ตอนนี้เรากำลังบอก Google ว่ามีฉบับภาษาอังกฤษ
> ทั้งที่ไม่มีอยู่จริง · Google ตรวจแล้วพบว่าไม่จริง จึงเลิกฟังทั้งหมด
> **เว็บเราจึงไม่มีตัวตนในผลค้นหาภาษาอังกฤษเลยแม้แต่หน้าเดียว**

## 3. ข้อจำกัดที่ห้ามละเมิด (จาก INC-0091)

แผนนี้ต้องอยู่ใต้กฎที่เพิ่งตั้งไว้เมื่อวานนี้เอง มิฉะนั้นจะพัง SSG ทั้งเว็บซ้ำรอย:

| กฎ | ที่มา | แผนนี้ทำตามอย่างไร |
| :--- | :--- | :--- |
| root layout ห้ามแตะ `headers()` / `cookies()` / `getServerLocale()` | ด่าน 10 ใน `test-seo-wave4.ts` | ภาษามาจาก **path segment** ตอน build ไม่ใช่จาก request |
| ห้ามมี `src/proxy.ts` หรือ `src/middleware.ts` | ด่าน 12 | ไม่ต้องใช้ redirect ฝั่งเซิร์ฟเวอร์เลย |
| `i18n/server.ts` ห้าม import `next/headers` | ด่าน 13 | ใช้แค่ `getDictionary(locale)` ที่รับ locale ตรง ๆ (มีอยู่แล้ว) |
| `HomeSeoContent` ต้องเป็น Server Component | ด่าน 11 | รับ `locale` เป็น prop แทนการเรียก `useLocale()` |
| ทุกหน้าสาธารณะต้อง prerender ได้ | INC-0091 | หน้า `/en/**` เป็น SSG ล้วน ไม่มี dynamic API |

**หัวใจของแผนนี้คือ: ภาษาถูกกำหนดตอน build จาก URL ไม่ใช่ตอน runtime จาก request**
ซึ่งเป็นสิ่งเดียวที่ทำให้ได้ทั้ง SEO สองภาษา **และ** SSG 100% พร้อมกัน

## 4. สถาปัตยกรรมที่เลือก และเหตุผลที่ไม่เลือกทางอื่น

### ✅ ทางที่เลือก — Route Group สองราก + `/en` เป็น wrapper บาง ๆ

```
src/app/
  (th)/layout.tsx          ← root layout ของไทย: <html lang="th">
  (th)/page.tsx            ← / (URL ไม่เปลี่ยน route group ไม่ปรากฏใน URL)
  (th)/cards/page.tsx
  (th)/cards/[id]/page.tsx
  ...
  (en)/layout.tsx          ← root layout ของอังกฤษ: <html lang="en">
  (en)/en/page.tsx         ← /en
  (en)/en/cards/page.tsx   ← /en/cards
  ...
  _shared/                 ← เนื้อหน้าจริง ใช้ร่วมกันทั้งสองภาษา
```

**ทำไมทางนี้**

1. **URL ไทยเดิมไม่ขยับแม้แต่ตัวเดียว** — route group `(th)` ไม่ปรากฏใน URL
   หน้าไทยที่ติดอันดับอยู่แล้ว 216 หน้าจึงปลอดภัย 100% ไม่ต้อง redirect สักเส้น
2. **ได้ `<html lang="en">` ตั้งแต่ไบต์แรก** — App Router รองรับ root layout หลายตัวต่อ route group
   ไม่ต้องรอ JavaScript มาแก้ `lang` ทีหลัง (ดีทั้ง Googlebot และโปรแกรมอ่านหน้าจอ)
3. **ยัง prerender ได้ทั้งหมด** — ไม่มีอะไรอ่าน request เลย

### ❌ ทางที่ไม่เลือก

| ทางเลือก | เหตุผลที่ตัดทิ้ง |
| :--- | :--- |
| `app/[lang]/...` (dynamic segment) | บังคับให้ไทยกลายเป็น `/th/...` → ต้อง redirect URL ที่ติดอันดับแล้วทั้ง 216 หน้า · เสี่ยงเสียอันดับที่อุตส่าห์สร้างมา |
| `middleware` ตรวจ `Accept-Language` แล้ว rewrite | **ผิดกฎ INC-0091 โดยตรง** — ทำให้ทุกหน้าเป็น dynamic อีกรอบ |
| ปล่อย `?lang=en` ไว้เหมือนเดิม | Google ทิ้ง hreflang ทิ้งทั้งชุดอยู่แล้ว (ข้อ 1) = เท่ากับไม่ทำอะไรเลย |
| `<html lang>` แก้ด้วย `useEffect` ฝั่ง client | ได้ผลครึ่งเดียว · HTML ดิบยังบอกว่าเป็นภาษาไทย |

### กลไกบังคับภาษาโดยไม่ต้องแก้คอมโพเนนต์สักตัว

`LocaleProvider` รับ prop ใหม่ `forcedLocale` (ค่าคงที่ที่ส่งมาตอน build ไม่ใช่ค่าจาก request):

```tsx
// src/app/(en)/layout.tsx
<html lang="en">
  <body>
    <SiteProviders forcedLocale="en">{children}</SiteProviders>
  </body>
</html>
```

เมื่อ `forcedLocale` มีค่า `LocaleProvider` จะ **ไม่อ่าน cookie/localStorage/query เลย**
และ `useLocale()` ทุกจุดในหน้านั้นคืน `en` ตั้งแต่ render แรก
→ **สาขา `isEnglish` ที่มีอยู่แล้วใน 25+ ไฟล์ ทำงานทันทีโดยไม่ต้องแก้อะไร**
→ ไม่มี hydration mismatch เพราะเซิร์ฟเวอร์กับไคลเอนต์ได้ค่าเดียวกันเสมอ

#### B3 · ต่อสายปุ่มสลับภาษาและกันถอยหลัง

- `LanguageSwitcher` ต้อง **นำทางไปยัง URL ฝาแฝด** ไม่ใช่แค่ `setLocale` ในหน่วยความจำ
  (`/cards/major-00` ⇄ `/en/cards/major-00`) — ใช้ `useRouter().push()` + เขียน cookie ไว้ให้หน้าที่ไม่มีฝาแฝด
- หน้าที่ไม่มีฝาแฝด (เช่น `/blog`) ให้ปุ่มยังทำงานแบบเดิม (สลับด้วย cookie ฝั่ง client)
- `?lang=en` ของเก่า: ยังทำงานเหมือนเดิมฝั่ง client ไม่ต้อง redirect (จะผิดกฎ INC-0091)
  แต่ไม่ถูกโฆษณาที่ไหนอีกแล้ว และ canonical ก็รวมกลับมาที่ URL สะอาดอยู่แล้ว

---

### 🅒 ขั้น C — แปลเนื้อบทความ แล้วค่อยเปิด `/en/blog` (งานเนื้อหา ไม่ใช่งานวิศวกรรม)

เพิ่มฟิลด์ `contentEn` ให้ `Article` แล้วแปลทีละบท · เปิด `/en/blog/[slug]`
**เฉพาะบทที่มี `contentEn` แล้วเท่านั้น** (กรองใน `generateStaticParams`)
บทที่ยังไม่แปลต้องไม่มีหน้าอังกฤษและไม่มี `hreflang` ชี้ไปหา

## 7. ด่านตรวจใหม่ที่ต้องเพิ่ม (ต่อจากด่านที่มีอยู่)

บทเรียนของคลังนี้: **"กฎที่ไม่มีเครื่องตรวจ คือกฎที่จะถูกละเมิดอีกแน่นอน"**

| ด่าน | ตรวจอะไร |
| :--- | :--- |
| **hreflang ต้องไม่โกหก** | ทุก `hreflang` ที่ประกาศ ต้องมีไฟล์หน้านั้นอยู่จริงในผลลัพธ์ build และ canonical ของปลายทางต้องชี้หาตัวเอง · ห้ามมี `?lang=` ในค่า `hreflang` เด็ดขาด |
| **คู่ TH/EN ต้องครบทั้งสองทาง** | ทุกหน้าที่มีฝาแฝด ต้องประกาศชี้หากันทั้งไปและกลับ (ขาดข้างเดียว Google ทิ้งทั้งคู่) |
| **หน้าอังกฤษต้องเป็นภาษาอังกฤษจริง** | สุ่มหน้า `/en/**` แล้วนับอักขระไทยใน HTML ดิบ — ต้องไม่เกินเกณฑ์ (กันหน้าที่ลืมแปล/ลืมส่ง locale หลุดออกไป) |
| **prerender ต้องไม่ถอยหลัง** | จำนวนหน้า SSG ต้อง ≥ ค่าที่บันทึกไว้ (ratchet) · หน้าใดกลายเป็น dynamic = ล้มทันที (กันซ้ำรอย INC-0091) |

## 9. ข้อควรตัดสินใจก่อนเริ่มขั้น B (เรียนเจ้าของโปรเจกต์)

ขั้น A ควรทำทันทีไม่ว่าจะตัดสินใจอย่างไร — เพราะเป็นการหยุดส่งสัญญาณผิดให้ Google

แต่ขั้น B (ราว 3 PR · แตะโครงสร้าง `src/app/` ทั้งหมด) ควรตัดสินใจบนความจริง 2 ข้อ:

1. **ตลาดคำค้นอังกฤษของไพ่ทาโรต์แข่งดุกว่าไทยมาก** — เจ้าถิ่นอย่าง biddytarot / labyrinthos
   สะสมลิงก์และอายุโดเมนมาสิบกว่าปี การขึ้นหน้าแรกด้วยคำกลางอย่าง _"the fool tarot meaning"_
   ไม่ใช่เรื่องที่เปิดเส้นทางแล้วจะได้มาเอง
2. **แต่ต้นทุนของเราต่ำผิดปกติ** — งานแปลที่ปกติแพงที่สุดเสร็จไปแล้ว (ไพ่ 78 ใบครบทุกฟิลด์
   ผัง 25 แบบครบทุกตำแหน่ง UI ครบ 162 คีย์) เหลือแค่งานวิศวกรรมเส้นทางล้วน ๆ

**ข้อเสนอ**: ทำขั้น A ทันที แล้วทำขั้น B **เฉพาะกลุ่ม `/en/cards/**` ก่อน (81 หน้า)**
วัดผลใน Search Console 4–6 สัปดาห์ ถ้ามี impression ขึ้นจริงค่อยขยายไป `/en/spreads/**`
ดีกว่าลงทุนทั้งก้อนแล้วมารู้ทีหลังว่าตลาดไม่ตอบ
