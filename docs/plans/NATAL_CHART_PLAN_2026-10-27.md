## 2. หลัก 5 ข้อ

1. **คำนวณในเครื่องผู้ใช้ทั้งหมด** — ไม่ยิง API · ไม่ใส่ข้อมูลเกิดใน URL · เก็บลง localStorage เมื่อผู้ใช้กดบันทึกเท่านั้น (ด่านตรวจ) · **ข้อยกเว้น 3 ทาง** (ผู้ใช้ลงมือเองทุกทาง): แท็บ "ถามแม่หมอ" และ "รายงานฉบับเต็ม" ส่งข้อมูลเกิดขึ้นเซิร์ฟเวอร์เมื่อติ๊กยินยอม (ไม่บันทึก) · ลิงก์ "ส่งผังนี้ให้เพื่อน" ใส่ข้อมูลเกิดหลัง `#` ของ URL (ไม่ถึงเซิร์ฟเวอร์) เมื่อผู้ใช้กดสร้างลิงก์ พร้อมคำเตือนให้ส่งเฉพาะคนที่ไว้ใจ · การเตือนทุกเช้าไม่มีข้อมูลเกิดเลย
2. **ไม่ใช้ AI ในที่ที่คำนวณได้** — ตำแหน่งดาวและคำอธิบายประกอบด้วยโค้ดจากเนื้อหาที่เขียนไว้ (`src/data/natal/content.ts`) ผลเดิมทุกครั้ง · AI ใช้แค่ "เรียบเรียง" สิ่งที่โค้ดคำนวณแล้ว (ถามแม่หมอ · ภาพรวมผัง · ภาพรวมในรายงาน) และทุกย่อหน้าต้องอ้างเรื่องเด่นที่มีจริง
3. **ตัวเลขต้องตรงฟ้าจริง** — ด่านเทียบ NASA JPL ไม่ใช่เทียบค่าที่โค้ดเราเคยคำนวณ
4. **ตัวคำนวณห้ามติดบันเดิลแรก** — ฟอร์ม 10 KB โหลดก่อน · ตัวคำนวณ (~33 KB gzip) + ผลผังโหลดตอนกดปุ่ม
5. **ไม่มีสัญลักษณ์ดาว/ราศี** (กฎเหล็ก 2) — ใช้ตัวย่อภาษาไทย/อังกฤษ มีคำอธิบายใต้วงผัง

## 3.11 รอบ 8 — ราศีนิรายนะแบบไทย/อินเดีย (Lahiri) (2026-10-28)

- เจ้าของเคาะ "ทำแบบ Lahiri" · ตัวเลือก "ระบบราศี" ในตั้งค่าขั้นสูง (ค่าเริ่มต้นยังเป็นสายนะ) · บันทึกไปกับผังที่บันทึก
- `lahiriAyanamsa()` นิยามเดียวกับ Swiss Ephemeris (23.245524743° ณ 21 มี.ค. 1956 + การหมุนควง IAU 2006) · `zodiacShift()` = อายนางศ์ + nutation ในลองจิจูด ลบออกจากลองจิจูดจริงของวันนั้น
- เลื่อนทุกจุดในผังเท่ากัน (ดาว · เรือน · ลัคนา · จุดอื่น ๆ) แล้วให้ดาวจร ดาวก้าวหน้า ผังวันเกิด ผังจันทร์คืน ผังคู่ (อีกคนใช้ระบบเดียวกันเสมอ) และดวงวันนี้ใช้อายนางศ์ของขณะนั้นเอง
- ตรวจ: J2000 ได้ 23.8571° ตรง SE ไม่เกิน 1″ · ดาวจิตรา (Spica) อยู่ 180° ±3′ ทุกยุค (นิยามของ Lahiri)
- ⚠️ คำอธิบายราศีและไพ่ Golden Dawn ยังเป็นของระบบตะวันตก ใช้ราศีนิรายนะแทนที่ (แจ้งผู้ใช้ในผลผัง) · ตำราไทยบางสำนักใช้อายนางศ์ต่างไปราว 1 องศา

## 6. กับดัก

- **`Date.UTC` ตีความปี 0–99 เป็น 1900+** — `timezone.ts` ตั้งปีใหม่ด้วย `setUTCFullYear` แล้ว อย่าลบ
- **ตารางไครอนมีถึง ค.ศ. 2100** — ขยายช่วงปีต้องรัน `scripts/gen-chiron-table.ts` ใหม่ (ต้องใช้ `NODE_USE_ENV_PROXY=1` บนเครื่องที่มีพร็อกซี)
- **ละติจูดเกิน 66 องศา** Placidus/Koch หาค่าไม่ได้ ➔ เปลี่ยนเป็น Porphyry และแจ้งผู้ใช้ (อย่าเดาค่า)
- **ป้ายไทยในตารางมุมสัมพันธ์** ใช้ `table-layout: fixed` ให้ป้ายยาวล้นไปทางขวา ถ้าเปลี่ยนเป็นกว้างอัตโนมัติ มือถือจะล้นจอหรือหักกลางคำ
- **portal ใต้ `body` ต้องมี `data-floating`** — layout มีกฎ `body > :not(.fixed):not([data-floating]):not([data-site-header]) { position: relative }` ไม่ใส่แล้วรายงานไปต่อท้ายหน้าแทนที่จะทับเต็มจอ (ด่าน 6.16)
- **ปฏิทินจันทรคติเป็นสูตรคำนวณ** — บางปีทางการเลื่อนอธิกวารต่างจากสูตร 1 วัน อย่า "แก้" สูตรให้ตรงปีเดียว ให้ผู้ใช้เลือกเดือนเอง
- **ห้าม import ตัวคำนวณ/เนื้อหาแบบ static ใน `NatalChartApp.tsx`** — บันเดิลแรกพุ่ง 30–40 KB (ด่านข้อ 7)
