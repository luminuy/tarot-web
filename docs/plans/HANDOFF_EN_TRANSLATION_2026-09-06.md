## 2. ทีมแปลต้องทำอะไร (สั้นที่สุด)

1. รับไฟล์ [`docs/i18n/pending-en.json`](../i18n/pending-en.json)
2. เติมคำแปลลงช่อง **`en`** ของแต่ละหน่วยเท่านั้น
3. ส่งไฟล์กลับ

**ห้ามแก้** ช่อง `id` · `th` · `target` · `kind` · `maxChars` เด็ดขาด
(`id` คือกุญแจที่ฝั่งพัฒนาใช้จับคู่คำแปลกลับเข้าโครงข้อมูล — เพี้ยนเมื่อไร คำแปลจะไปลงผิดบทความ)

โครงหน้าตาแต่ละหน่วย:

```json
{
  "id": "article:tarot-love-reading-guide:content",
  "target": "src/data/articles.ts → ARTICLES[\"tarot-love-reading-guide\"].contentEn",
  "kind": "markdown",
  "th": "## 1. ...",
  "en": ""
}
```

สร้างไฟล์ใหม่ได้ทุกเมื่อด้วย:

```bash
npm run i18n:export
```

ดูสรุปปริมาณงานอย่างเดียว (ไม่เขียนไฟล์):

```bash
npm run i18n:status
```

## 4. กติกาการแปล (สำคัญกว่าความเร็ว)

### 4.1 ไม่ใช่การแปลตรงตัว — โดยเฉพาะหัวข้อ SEO

คนไทยกับคนอังกฤษ **ค้นด้วยคำคนละชุด** หน่วยชนิด `seo-title` · `meta-description` · `faq-q`
ให้ **เขียนใหม่ให้ตรงกับวิธีที่คนอังกฤษค้นจริง** ไม่ใช่แปลคำต่อคำ

| ไทย (ต้นทาง) | ❌ แปลตรงตัว | ✅ เขียนใหม่ให้ตรงคำค้น |
| :--- | :--- | :--- |
| ดูดวงความรัก 3 ใบ เขารู้สึกยังไง | Love fortune 3 cards how he feels | 3-Card Love Tarot Spread: How They Really Feel |
| ไพ่ยิปซีกลับหัวอ่านยังไง | How to read upside-down gypsy cards | Reversed Tarot Cards: What They Actually Mean |
| แม่หมอ AI | AI mother fortune teller | AI tarot reader |

> ส่วนหน่วยชนิด `markdown` · `prose` · `faq-a` ให้ **รักษาสาระและลำดับความคิดเดิมไว้ครบ**
> ปรับสำนวนให้เป็นภาษาอังกฤษที่เป็นธรรมชาติได้ แต่ห้ามตัดเนื้อหาทิ้งหรือเติมข้อมูลใหม่ที่ต้นฉบับไม่มี

### 4.2 คงโครงสร้าง Markdown ไว้ทุกตัวอักษร

หน่วย `kind: "markdown"` เป็น Markdown ที่เว็บเรนเดอร์จริง ต้องคง:

- `## หัวข้อ` — คงระดับ `##` / `###` เดิม **และจำนวนหัวข้อต้องเท่าเดิม**
- `**ตัวหนา**` · `*ตัวเอียง*` · `---` เส้นคั่น · รายการ `1.` และ `-`
- ลิงก์ `[ข้อความ](/cards/major-00)` — **แปลเฉพาะข้อความในวงเล็บเหลี่ยม ห้ามแตะ URL ในวงเล็บกลม**
  (ฝั่งพัฒนาจะเติม `/en` ให้เองอัตโนมัติ)

### 4.3 ชื่อไพ่และชื่อผัง — ใช้ของที่มีอยู่แล้ว ห้ามคิดใหม่

ไพ่ 78 ใบและผัง 25 แบบ **มีชื่ออังกฤษที่เป็นทางการอยู่ในระบบแล้ว** ต้องใช้ตรงนั้นเป๊ะ
เช่น `The Fool` · `The Hanged Man` · `Three of Swords` · `Celtic Cross`

ดูรายชื่อทั้งหมดได้จากหน้าเว็บที่เปิดแล้ว: <https://seertarot.net/en/cards/all>

> ⚠️ **กฎเหล็กข้อ 14 (Zero Fabricated Cards)**: ห้ามกุชื่อไพ่ที่ไม่มีในสำรับ 78 ใบเด็ดขาด
> ถ้าเจอข้อความไทยที่อ้างถึงไพ่ที่หาชื่ออังกฤษไม่เจอ **ให้ทักกลับมาถาม อย่าเดา**

### 4.5 น้ำเสียง

ต้นฉบับไทยเป็นน้ำเสียง "แม่หมอที่รู้จริงแต่ไม่ขู่" — ฉบับอังกฤษให้เป็น
**นักอ่านไพ่มืออาชีพที่พูดตรง ไม่ขายของ ไม่ทำให้กลัว**

- ❌ หลีกเลี่ยง: "destiny has decided", "the cards command", "you must", ประโยคอุทานเยอะ
- ✅ ใช้: ประโยคบอกเล่าเรียบ ๆ · อธิบายเหตุผล · ให้ผู้อ่านตัดสินใจเอง
- ห้ามใช้อิโมจิทุกชนิดในเนื้อหา (**กฎเหล็กข้อ 2**)
- ห้ามให้คำแนะนำทางการแพทย์ กฎหมาย หรือการเงินแบบชี้ขาด (หมวด `health` / `money` ระวังเป็นพิเศษ)

### 4.6 เพดานความยาวที่ต้องเคารพ

## 6. งานที่ฝั่งพัฒนาต้องทำ (ไม่ใช่งานทีมแปล)

บันทึกไว้ให้ครบ เพื่อให้ Agent/นักพัฒนาคนถัดไปรับช่วงได้ทันทีที่คำแปลกลับมา

### D-1 · เพิ่มฟิลด์ภาษาอังกฤษในโครงข้อมูล

```ts
// src/data/articles.ts
export interface Article {
  // ...ของเดิม
  titleEn?: string;
  descriptionEn?: string;
  tocEn?: ArticleTocItem[];
  faqsEn?: ArticleFaq[];
  contentEn?: string;   // ← ตัวชี้ขาดว่าบทความนี้เปิดหน้าอังกฤษได้หรือยัง
}

// src/data/spread-topics.ts
export interface SpreadTopic {
  // ...ของเดิม
  seoTitleEn?: string;
  metaDescriptionEn?: string;
  titleEn?: string;
  headingEn?: string;
  taglineEn?: string;
  editorialIntroEn?: string[];
  faqsEn?: { question: string; answer: string }[];
}
```

### D-2 · สคริปต์ import คำแปลกลับ

`scripts/i18n-import.ts` — อ่านไฟล์ที่ทีมแปลส่งกลับ แล้วเขียนลงโครงข้อมูลตามช่อง `target`
ต้องล้มทันทีถ้า: `id` ไม่ตรงกับต้นทาง · `th` ถูกแก้ · `en` ว่างแต่ถูกทำเครื่องหมายว่าเสร็จ
· จำนวนหัวข้อ `##` ใน `contentEn` ไม่เท่ากับต้นฉบับ

### D-3 · เปิดหน้าอังกฤษแบบ "เฉพาะที่แปลแล้ว"

```ts
// src/app/(en)/en/blog/[slug]/page.tsx
export function generateStaticParams() {
  // เฉพาะบทความที่มี contentEn เท่านั้น — บทที่ยังไม่แปลจะไม่มีหน้าอังกฤษ ไม่มี hreflang
  return ARTICLES.filter((a) => a.contentEn).map((a) => ({ slug: a.slug }));
}
```

และแก้ `EN_TWIN_EXCEPTIONS` / `EN_TWIN_EXCEPTION_PREFIXES` ใน
[`src/lib/i18n/paths.ts`](../../src/lib/i18n/paths.ts) ให้ตัดสินรายบทความจากการมี `contentEn`
แทนการยกเว้นทั้งกิ่ง

### D-4 · ขยายด่านตรวจที่ 35

[`scripts/qa/test-en-routing.ts`](../../scripts/qa/test-en-routing.ts) ต้องเพิ่ม:
- บทความที่มี `contentEn` ต้องมีหน้า `/en/blog/<slug>` และ hreflang ครบสองทาง
- บทความที่ **ไม่มี** `contentEn` ต้องไม่มีทั้งสองอย่าง
- `contentEn` ต้องมีจำนวนหัวข้อ `##` เท่ากับ `content` และไม่มีอักขระไทยหลงเหลือ

### D-5 · `/privacy` — **ไม่ใช่งานแปล**

ข้อความ PDPA เป็นเอกสารทางกฎหมาย การแปลโดยไม่ได้ทบทวนทางกฎหมาย
อาจสร้างข้อผูกพันที่ต่างจากฉบับไทย → **ต้องให้ที่ปรึกษากฎหมายร่างฉบับอังกฤษเอง**
ไม่ใช่ส่งเข้าคิวแปล · จนกว่าจะมี ให้ `/privacy` คงเป็นภาษาไทยและไม่ประกาศ hreflang (สถานะปัจจุบันถูกต้องแล้ว)

## 7. เกณฑ์รับงาน (Definition of Done)

ทีมแปลถือว่าส่งงานครบเมื่อ:

- [ ] ทุกหน่วยในล็อตที่รับ มีช่อง `en` ที่ไม่ว่าง
- [ ] ไม่มีอักขระไทยหลงเหลือในช่อง `en` แม้แต่ตัวเดียว
- [ ] `seo-title` ทุกหน่วย ≤ 60 อักขระ · `meta-description` ทุกหน่วย ≤ 155 อักขระ
- [ ] หน่วย `markdown` มีจำนวนหัวข้อ `##`/`###` และลำดับตรงกับต้นฉบับ
- [ ] URL ในลิงก์ Markdown ไม่ถูกแก้แม้แต่ตัวเดียว
- [ ] ชื่อไพ่/ผังทุกจุดตรงกับรายชื่อทางการที่ <https://seertarot.net/en/cards/all>
- [ ] ศัพท์ตรงตามอภิธานศัพท์ข้อ 4.4 ทั้งหมด
- [ ] ไม่มีอิโมจิในเนื้อหา

ฝั่งพัฒนาจะรันด่านตรวจซ้ำอีกชั้นตอน import — ถ้าไม่ผ่านจะส่งรายการที่ต้องแก้กลับไปเป็นข้อ ๆ
