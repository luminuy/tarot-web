     export GROQ_API_KEY=<คีย์ของนักพัฒนา>        # ผู้ผลิตคำอ่าน (บังคับ)
     export GEMINI_API_KEY=<คีย์ของนักพัฒนา>      # ผู้ตัดสิน (ไม่ใส่ = ตรวจด้วยโค้ดอย่างเดียว)

> 📌 `GOOGLE_API_KEY` ใช้แทน `GEMINI_API_KEY` ได้ (สคริปต์อ่านทั้งสองตัว)
> 📌 ถ้าบ้านคุณยิงผ่าน Cloudflare AI Gateway ให้ตั้ง `CF_AI_GATEWAY_ACCOUNT_ID` · `CF_AI_GATEWAY_ID`

### B-03 · บังคับหลักฐานในโครงสร้าง `visualAnchor` (~1.5 วัน · โทเค็น +20%)

> ⚠️ **เทียบแบบหลวม ไม่ใช่ substring ตรง ๆ** — ตัดคำไทยด้วย `Intl.Segmenter("th")` แล้วนับคำร่วม ≥ 1 คำที่ยาว ≥ 3 ตัวอักษร
> ⚠️ **เริ่มที่ระดับ warn เก็บสถิติ 1 สัปดาห์ก่อน** ค่อยตัดสินว่าจะยกเป็น fatal

## 6.1 อ่านผลเทียบให้ถูก — กับดักที่เพิ่งเหยียบมา

`--compare` **เทียบเฉพาะเคสที่สำเร็จทั้งสองรอบเท่านั้น** และพิมพ์ความครอบคลุมกำกับไว้เสมอ:

```
ความครอบคลุม   20260911-1: 16/30 เคส → 20260911-2: 30/30 เคส
เคสที่สำเร็จทั้งสองรอบ (ใช้เทียบจริง): 16 เคส
```

**ทำไมต้องเป็นแบบนี้**: baseline สำเร็จ 16/30 ถ้ารอบใหม่สำเร็จ 30/30 แล้วเอา "ค่าเฉลี่ยรวม" มาเทียบกันดื้อ ๆ ตัวเลขที่ได้บอกแค่ว่า *ชุดเคสเปลี่ยนไป* ไม่ได้บอกว่าคำอ่านดีขึ้นจริง — แต่หน้าจอจะขึ้น `🟢 ดีขึ้น` ให้อ่านอย่างมั่นใจ (เดิมเป็นแบบนั้นจริง ๆ แก้แล้วพร้อมเทสต์ล็อกไว้)

ถ้าเคสที่ทับกันน้อยกว่า 60% ของชุดใหญ่ จะขึ้นเตือนว่า **ยังตัดสินแทนทั้งชุดไม่ได้** ➔ ให้ไปแก้สาเหตุที่เคสล้มก่อน อย่าเพิ่งสรุป

## 6.2 ด่านใหม่ที่กันไม่ให้หลุดซ้ำ

`npm run repo:verify` มีด่าน **🧑‍⚖️ เวอร์ชัน prompt มีผลวัด ai:judge รองรับ** แล้ว (ไม่เรียกโมเดล ต้นทุน 0):

| สถานการณ์ | ผล |
| :--- | :--- |
| PR ขึ้น `PROMPT_VERSION` แต่ไม่มีรายงานของเวอร์ชันใหม่ | 🔴 **ตก** |
| ไฟล์รายงานเสียรูป / เวอร์ชันในไฟล์ไม่ตรงชื่อไฟล์ / ไม่มีเคส | 🔴 **ตก** |
| เวอร์ชันปัจจุบันไม่มีรายงาน (หนี้ค้างจากรอบก่อน) | 🟡 เตือนทุกครั้งที่รัน |
| รายงานล่าสุดครอบคลุมเคสต่ำกว่า 80% | 🟡 เตือน |

> ตั้งใจให้ข้อ 3-4 เป็น "เตือน" ไม่ใช่ "ตก" เพราะจะกลายเป็นบล็อกทุก PR ทั้งเว็บด้วยหนี้ของงาน AI ซึ่งไม่ได้สัดส่วน
> แต่ข้อ 1-2 ตกจริง และ**ทดสอบแล้วว่าตกจริงทั้ง 3 เคส** ไม่ใช่ด่านหลอกที่ตกไม่ได้
