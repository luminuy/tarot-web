**สามอย่างที่ต้องรู้ก่อนอ่านอย่างอื่น:**

1. 🔴 **เรายังพิสูจน์ไม่ได้ว่าคำอ่านแม่นขึ้นหรือแย่ลง**
   คอลัมน์ `judge_score` มีอยู่ในตาราง `reading_quality` ตั้งแต่ PR #245 แต่ **ไม่มีโค้ดบรรทัดไหนในทั้ง repo เขียนค่าลงไปเลย**

   ➔ ทุกงาน "ทำให้แม่นขึ้น" ที่ทำต่อจากนี้จะเป็นการเดาล้วน ๆ จนกว่าจะปิดข้อนี้

2. 🔴 **ไม่มีด่านตรวจ "ภาษาไทยถูกไหม" อยู่เลยแม้แต่ด่านเดียว**
   ที่มีคือ `src/lib/ai/language.ts` ซึ่งเป็นด่าน **"ไม่ใช่ภาษาต่างด้าว"** (กันอักษรจีน/ญี่ปุ่น/เกาหลี) คนละเรื่องกับ **"ภาษาไทยถูกต้อง"**

3. 🟠 **คลื่นที่ 2-3 ของแผนเดิมยังไม่ได้เริ่มสักงาน**
   `visualAnchor` (บังคับให้อ้างภาพไพ่จริง) · ถามกลับก่อนสับไพ่ · คลังตัวอย่างคำอ่าน — ยังไม่มีในโค้ด

### A-01 · เครื่องตรวจภาษาไทย (Thai Quality Linter) 🔥 รากฐานของทุกอย่าง

**ไฟล์ใหม่**: `src/lib/ai/thai-quality.ts` · **เทสต์**: `scripts/qa/test-thai-quality.ts`

ตรวจด้วยโค้ดล้วน **ไม่เรียกโมเดลเลย ต้นทุน AI = 0** ตามปรัชญาเดียวกับ `consistency.ts`

```ts
export type ThaiIssueCode =
  // ── ระดับ fatal: เขียนผิดชัดเจน แก้อัตโนมัติได้ ────────────────
  | "DOUBLE_SARA_E"        // "เเสง" (เ+เ) ต้องเป็น "แสง" (แ)
  | "PARTICLE_MISMATCH"    // "นะค่ะ" → "นะคะ" · "ไหมค่ะ" → "ไหมคะ"
  | "DUP_DIACRITIC"        // วรรณยุกต์/สระซ้อนซ้ำ "ก่่อน"
  | "ORPHAN_DIACRITIC"     // วรรณยุกต์ลอยไม่มีพยัญชนะนำ
  | "INVISIBLE_CHAR"       // zero-width ​-‍ ﻿
  // ── ระดับ warn: สไตล์บ้านนี้ ─────────────────────────────────
  | "MAIYAMOK_SPACING"     // "ค่อยๆ" → "ค่อย ๆ" (ยึดราชบัณฑิตยสภา)
  | "LATIN_LEAK"           // คำอังกฤษที่ไม่ใช่ชื่อไพ่ 1909 เช่น "energy"
  | "ROBOT_PHRASE"         // "ตามหลักการของไพ่ระบุว่า" (prompt ห้ามไว้แต่ไม่เคยบังคับ)
  | "BARNUM_PHRASE"        // "ทุกอย่างจะดีขึ้นเอง" ใช้กับใครก็ได้
  | "REPETITIVE_NGRAM"     // วลี 8 ตัวอักษรเดิมโผล่ ≥ 3 ครั้งในคำอ่านเดียว
  | "WORD_SPLIT_SPACE";    // ช่องว่างแทรกกลางคำไทย

export interface ThaiQualityResult {
  ok: boolean;
  fatal: boolean;
  score: number;              // 0-100 (100 = ไม่มี issue) เก็บลง reading_quality.thai_score
  issues: ThaiIssue[];
  fixed?: string;             // ข้อความหลังแก้อัตโนมัติ (เฉพาะ issue ที่แก้ได้อย่างปลอดภัย)
}

export function checkThaiQuality(text: string, opts?: ThaiQualityOptions): ThaiQualityResult;
export function polishThai(text: string): string;   // แก้เฉพาะกลุ่มที่ปลอดภัย 100%
```

> ⚠️ **กับดักผลบวกลวง — บทเรียนตรงจาก `consistency.ts`**

> **ทำเป็นงานสุดท้ายของคลื่น B** เพราะมี UI ด้วยและกินโควตาเพิ่ม — ต้องมีเครื่องวัดพร้อมก่อน

หลังผู้ใช้กรอกคำถามใน `IntentionAltarInput` เรียกโมเดลเล็ก 1 ครั้ง:

```ts
{ needsClarification: boolean; question?: string; reason?: string }
```

ถ้าต้องถาม → แสดง **1 คำถาม (ข้ามได้)** → คำตอบเก็บเข้า `intake` ที่มีอยู่แล้ว → เข้าพิธีสับไพ่ตามปกติ

**ทำไมข้อนี้คุ้มที่สุด**
- เกิด **ก่อน** พิธีสับไพ่ ➔ **ไม่กระทบ TTFB ของคำอ่านเลยแม้แต่มิลลิวินาทีเดียว**
- เข้ากับพิธีกรรมพอดี — แม่หมอจริงก็ถามกลับ ไม่ใช่ขั้นตอนแปลกปลอม
- ข้อมูลที่ได้ทำให้คำอ่าน "แม่น" ขึ้นแบบที่ prompt engineering ทำไม่ได้

**ข้อบังคับ**
- ข้ามได้เสมอ · ถามแค่ **1 ข้อ** · คำถามที่ชัดอยู่แล้วต้องไม่ถาม
- ต้องผ่าน `isAiCapReached()` และนับด้วย `recordAiCall()` — **บทเรียน INC-0074 ตรง ๆ**
- เพดานเต็ม / โมเดลล้ม / เกิน 3 วินาที → **ข้ามเงียบ ๆ** ไม่บล็อกผู้ใช้
- คำถามที่ AI ถามกลับต้องผ่าน `checkThaiQuality()` ก่อนแสดง (มันคือข้อความที่ผู้ใช้เห็นเหมือนกัน)

**✅ เกณฑ์ผ่าน**
- [ ] "เขาจะกลับมาไหม" → ถามกลับ · "ควรย้ายไปทำงานบริษัท A ที่เสนอเงินเดือนสูงกว่า 20% แต่ต้องย้ายจังหวัดไหม" → **ไม่ถาม**
- [ ] กดข้าม → ไปต่อทันที
- [ ] เพดานเต็ม → ข้ามเงียบ ไม่มี error ให้ผู้ใช้เห็น
- [ ] `judge_score` ของเคสที่ผ่านการถามกลับ **สูงกว่า** เคสที่ไม่ผ่าน อย่างมีนัย
- [ ] อัตราคนกดข้าม < 40% (ถ้าสูงกว่านี้ = คำถามน่ารำคาญ ต้องแก้เกณฑ์การถาม)

## 6. ภาคผนวก A — กติกาภาษาไทยฉบับบ้านนี้ (House Thai Style)

> เอกสารนี้คือ **แหล่งความจริงเดียว** ของกติกาภาษาไทย · `thai-quality.ts` ต้องอ้างกลับมาที่นี่ในคอมเมนต์หัวไฟล์

### A.1 กลุ่ม fatal — ผิดชัดเจน แก้อัตโนมัติได้ปลอดภัย

| รหัส | ผิด | ถูก | วิธีจับ |
| :--- | :--- | :--- | :--- |
| `DOUBLE_SARA_E` | `เเสง` (U+0E40 ×2) | `แสง` (U+0E41) | `/เเ/g` → `แ` |
| `PARTICLE_MISMATCH` | `นะค่ะ` `ไหมค่ะ` `มั้ยค่ะ` `หรือค่ะ` `เหรอค่ะ` | `นะคะ` `ไหมคะ` `มั้ยคะ` `หรือคะ` `เหรอคะ` | รายการปิด (closed list) เท่านั้น |
| `PARTICLE_MISMATCH` | `ขอบคุณคะ` `ค่ะ?` ท้ายประโยคคำถาม | `ขอบคุณค่ะ` · `คะ?` | รายการปิด |
| `DUP_DIACRITIC` | `ก่่อน` (วรรณยุกต์ซ้อน) | `ก่อน` | `/([่-๋])\1+/g` |
| `ORPHAN_DIACRITIC` | วรรณยุกต์ลอยไม่มีพยัญชนะนำหน้า | ลบทิ้ง | lookbehind หาพยัญชนะ `ก-ฮ` |
| `INVISIBLE_CHAR` | `​` `‌` `‍` `﻿` | ลบทิ้ง | regex ตรง |

> ✅ **กฎ ค่ะ/คะ ที่ใช้จริง**: `ค่ะ` = ลงท้ายประโยคบอกเล่า · `คะ` = ลงท้ายประโยคคำถาม หรือมาหลัง `นะ`
> ⚠️ **ห้ามใช้กฎทั่วไปเดา** เช่น "เจอ `?` แล้วเปลี่ยน `ค่ะ` เป็น `คะ` ทุกกรณี" — ประโยคซ้อนจะพัง
> **ใช้เฉพาะรายการปิดที่ระบุข้างบนเท่านั้น** ปลอดภัยกว่าและครอบคลุมความผิดพลาดจริง 90%+ ของโมเดล

### A.2 กลุ่ม warn — สไตล์บ้านนี้ ต้องเฝ้าสถิติก่อนบังคับ

| รหัส | กติกา | หมายเหตุ |

| `REPETITIVE_NGRAM` | วลีไทย 8 ตัวอักษรเดิมซ้ำ ≥ 3 ครั้งข้าม `cards[].reading` | จับ "อ่านทุกใบเหมือนกันหมด" |
| `WORD_SPLIT_SPACE` | ช่องว่างแทรกกลางคำ (ท่อนหลัง ≤ 2 ตัวอักษรและขึ้นต้นด้วยสระ/วรรณยุกต์) | **warn ตลอดกาล ห้ามยกเป็น fatal** |
