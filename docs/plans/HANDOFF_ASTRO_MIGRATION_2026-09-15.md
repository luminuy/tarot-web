## 0. ทำไมต้องย้าย (ตัวเลขจริง)

หน้าเนื้อหาไม่มีสถานะอะไรให้จำ ผู้ใช้แค่อ่าน แต่ Next.js ส่ง React runtime + router +

และที่สำคัญกว่าตัวเลข: **แท็ก `<script>` ในหน้าไพ่รายใบลดจาก 20 ก้อนเหลือ 0 ก้อน**

## 1. สถาปัตยกรรมที่ใช้ (อ่านก่อนแตะอะไรทั้งสิ้น)

```
next build  ➔ .next/            ➔ opennextjs-cloudflare build ➔ .open-next/{worker.js,assets}
astro build ➔ dist/             ─────────────────────────────┐
                                                             ▼
                              scripts/merge-astro-assets.ts คัดลอก dist/ ทับลง .open-next/assets
                                                             ▼
                               Cloudflare: ไฟล์ static มาก่อน Worker เสมอ
```

* หน้าที่ย้ายแล้ว = ไฟล์ HTML ใน assets ➔ ตอบที่ขอบ ไม่ผ่าน Worker
* หน้าที่ยังไม่ย้าย + `/api/*` + `sitemap.xml` ➔ ตกไปที่ Worker ตามเดิม (ไม่มีอะไรเปลี่ยน)
* `wrangler.jsonc` เขียน `html_handling` · `not_found_handling` · `run_worker_first` ไว้ตรง ๆ แล้ว
  (อย่าลบ — พฤติกรรมของครึ่งเว็บไม่ควรขึ้นกับค่าเริ่มต้นที่ผู้ให้บริการอาจเปลี่ยน)

### ชั้นแปลงปลั๊ก — หัวใจที่ทำให้ไม่ต้องเขียนคอมโพเนนต์ใหม่เลยสักตัว

`astro.config.mjs` ชี้ `next/link` · `next/navigation` · `next/script` ไปที่ `astro/shims/*`
ตอนบิลด์ด้วย Astro เท่านั้น · คอมโพเนนต์ทั้ง 90 ตัวใน `src/components/**` จึงใช้ได้
**ทั้งสองเครื่องมือโดยไม่ต้องแก้แม้แต่บรรทัดเดียว**

> ⚠️ ห้ามไล่แก้ `src/components/**` ให้เลิกใช้ `next/link` เพื่อการนี้
> ตราบใดที่ Next ยังเรนเดอร์หน้าแอปอยู่ ทั้งสองฝั่งต้องใช้ไฟล์เดียวกัน

### กติกา island (ผิดข้อเดียวบันเดิลพุ่ง 10 เท่า)

1. **ห้ามนำเข้าข้อมูลก้อนใหญ่ในไฟล์ที่มี island** — Astro มัดรวมทั้งไฟล์ลงบันเดิลไคลเอนต์
   เผลอ `import { cardById }` ครั้งเดียว บันเดิลพุ่งจาก 24 KB เป็น **980 KB** (วัดจริง)
2. **คอมโพเนนต์ที่เรนเดอร์เป็น HTML แล้วจบ ต้องอยู่คนละไฟล์กับ island**
   (ดู `astro/components/` เทียบกับ `astro/islands/`)
3. **ส่วนที่ต้องโต้ตอบให้ส่งเข้าไปทาง slot** ไม่ใช่เรนเดอร์ซ้อนใน React
   island วางซ้อนข้างใน React ไม่ได้ — มันต้องอยู่ระดับเทมเพลตของ Astro
   (ตัวอย่าง: `CardsIndexBody` รับ `explorer` · `CardDetailView` รับ `related`)
4. **ใช้ `client:idle` เป็นค่าเริ่มต้น** ห้าม `client:load` ถ้าไม่ใช่ของที่ผู้ใช้ต้องกดทันที
5. **ภาษาถูกตรึงตาม URL** ในหน้าที่เรนเดอร์ด้วย Astro (ทุก island ต้องรับ `locale` แล้วส่งเข้า
   `forcedLocale`) — เหตุผลเต็มอยู่ในหัวไฟล์ `astro/layouts/BaseLayout.astro`

## 3. คลื่นถัดไป (เรียงตามลำดับที่ควรทำ)

### ✅ คลื่น 2 — `/blog/**` และ `/spreads/**` (เสร็จแล้ว)
ย้ายครบ 118 หน้า: `/blog` · `/blog/<slug>` · `/spreads` · `/spreads/<ผัง>` · `/spreads/topic/<หมวด>` ทั้งสองภาษา
* ย้าย `BlogIndexClient` · `ArticleReadingClient` ออกจาก `src/app/**` มาไว้ที่ `src/components/blog/`
* แยกแกนกลางแบบซิงโครนัสออกจากตัวห่อ async ทุกไฟล์ (`BlogDetailContent` · `SpreadDetailContent` · `SpreadTopicContent`)
  พร้อมแยกตัวสร้าง metadata เป็นแบบซิงโครนัสด้วย — ตรรกะ SEO ยังมีที่เดียวเหมือนเดิม
* **ไม่สร้างหน้าให้ slug เก่าของบทความอีกต่อไป** — ปล่อยให้ตกไปที่ Worker แล้วโดน `redirects()`
  ใน `next.config.ts` เด้ง 301 ให้ (ดีกว่าเดิมที่ Next สร้างเปลือกหน้าเปล่าแล้วเด้งฝั่งไคลเอนต์)
* ⚠️ **งานที่ยังค้าง**: `/blog` คือหน้าที่ TBT แย่ที่สุดของเว็บ (660 ms · ISSUE-043)
  หลังย้าย HTML ลด 35 ➔ 23 KB และ JS ลด 174 ➔ 143 KB — **ต้องยิง Lighthouse วัดซ้ำ
  แล้วบันทึกผลลง `KNOWN_ISSUES.md` ก่อนปิดเคส** ห้ามสรุปเองจากตัวเลขสองตัวนี้

### ✅ คลื่น 3 — หน้าข้อมูลคงที่ (เสร็จแล้ว)

## 3.5 ผลกระทบของการ "ถอด Next ทิ้ง" และเหตุผลที่ยังไม่ทำ (ตรวจโค้ดจริง 2026-09-18)

> 📌 หัวข้อนี้คือคำตอบของคำถาม "ถ้าไม่ย้ายต่อ จะมีผลอะไรไหม" — **ไม่มีผลกับผู้ใช้ SEO
> หรือค่าใช้จ่ายเลย** เพราะหน้าที่คนและ Google เข้าเป็นไฟล์สแตติกที่ขอบอยู่แล้ว
> ส่วน `/api/*` ต้องวิ่งผ่าน Worker ไม่ว่าจะเป็นเครื่องมือไหน ย้ายแล้วค่าคำขอเท่าเดิม

### งานที่คลื่น 5 ต้องทำจริง (ปริมาณวัดจากโค้ด)

| ก้อน | ปริมาณจริง | ความยาก |
|---|---|---|
| `/api/*` 68 เส้น | ใช้แค่ `request.headers` (40 จุด) · `request.json` (31 จุด) · `NextResponse.json` (68 จุด) | 🟢 เป็น Web API มาตรฐานเกือบล้วน · `NextResponse.json` ➔ `Response.json` แทบ 1:1 |
| `cookies()` จาก `next/headers` | **16 ไฟล์** รวม `session.ts` · `resolve-session.ts` · `require-admin.ts` · `reader-auth.ts` · `privileged.ts` · `guest.ts` | 🔴 **หนักที่สุด** — Next เรียกลอย ๆ ได้ (AsyncLocalStorage) แต่ Astro ต้องส่ง `context` เข้าไปทุกชั้น ➔ รื้อลายเซ็นฟังก์ชันทั้งชั้น auth |
| 9 หน้าที่เหลือ | 5 หลังบ้าน + 4 ไดนามิก | 🟡 ต้องมี SSR ➔ **ต้องใส่ `@astrojs/cloudflare` adapter** ซึ่งหัว `astro.config.mjs` ข้อ 3 ห้ามไว้ |
| `next.config.ts` | redirects 10 กฎ · headers 7 ชุด | 🟡 ดูกับดักข้างล่าง |
| ไฟล์พิเศษ | `sitemap.ts` · `robots.ts` · `manifest.ts` · `error.tsx` · `not-found.tsx` · `loading.tsx` | 🟡 ไม่มีของเทียบตรง ต้องเขียนใหม่เป็น endpoint ของ Astro |
| ด่านตรวจ | **9 สคริปต์** อ่าน `.next`/`.open-next` ผ่าน `scripts/qa/lib/rendered-pages.ts` | 🟡 ไม่แก้ = ด่าน "ผ่านเงียบ" แบบ INC-0165 |

**ของที่ไม่ต้องห่วงแล้ว**: shim ครบทั้ง 4 ตัว (`next/link` · `navigation` · `script` · `dynamic`)
ทำให้คอมโพเนนต์ที่ใช้ร่วมไม่ต้องแตะ · `getCloudflareContext()` ถูกห่อไว้ที่
`src/lib/platform/cf.ts` จุดเดียว · `next/image` เหลือผู้ใช้รายเดียวคือ `/admin/login`

### กับดักสองข้อที่จะทำให้คลื่น 5 พังแบบเงียบ

1. **ใส่ adapter ผิดโหมด = ลากหน้าสแตติกกลับเข้า Worker** — เสียค่าคำขอและช้าลง
   ซึ่งคือสิ่งที่สี่คลื่นที่ผ่านมาอุตส่าห์แก้ · `astro.config.mjs` เขียนห้ามใส่ adapter ไว้
   ด้วยเหตุผลนี้ ถ้าวันหนึ่งต้องใส่จริง **ต้องแก้คอมเมนต์นั้นพร้อมอธิบายโหมดที่เลือก**
2. **กฎ `www ➔ apex` ย้ายไป `public/_redirects` ไม่ได้** — Cloudflare `_redirects`
   ไม่รองรับเงื่อนไข host ที่ `has: [{ type: "host" }]` ใน `next.config.ts` ทำอยู่
   ➔ ต้องตั้งเป็น **Redirect Rule บน Cloudflare Dashboard ซึ่งต้องใช้สิทธิ์เจ้าของ**
   (ข้อนี้ถูกเขียนเตือนไว้แล้วในคอมเมนต์ของกฎนั้นเอง) · ยังมี redirect ลิงก์เก่าอีก 8 เส้น
   (`/tarot` · `/love` · `/daily-tarot` · slug บทความเก่า 2 เส้น ฯลฯ) ที่หายแล้ว 404 ทันที

## 4. กับดักที่เหยียบมาแล้ว (อย่าเหยียบซ้ำ)

| กับดัก | อาการ | บันทึก |
|---|---|---|
| `import` ข้อมูลในไฟล์ island | บันเดิล 24 KB ➔ **980 KB** | คอมเมนต์ใน `astro/islands/CardDetailRoot.tsx` |
| กฎ `/cards/*` ใน `_headers` | หน้าไพ่ถูกแคช 1 ปีแบบ immutable แก้แล้วไม่ถึงผู้ใช้ | INC-0166 |
| ลำดับกฎใน `sw.js` | หน้าไพ่ถูกเสิร์ฟแบบ cache-first · ออฟไลน์ได้ 408 แทนหน้าสำรอง | INC-0164 |
| ด่านงบน้ำหนักมองไม่เห็น JS ของ Astro | รายงาน 0 KB แล้วขึ้นเขียว | INC-0165 |
| `build.format: "directory"` | เส้นทางกลายเป็น `/cards/x/index` ด่านทั้งชุดมองไม่เห็นหน้า | คอมเมนต์ใน `astro.config.mjs` |
| `*/` ในคอมเมนต์ไฟล์ `.tsx` | บิลด์ Astro ล้มด้วย "Unexpected token" ที่บรรทัดคอมเมนต์ | — |
| เขียน `<link rel="preload">` เองใน `<head>` ของ Next | React 19 ยกขึ้นให้อีกชุด ได้แท็กซ้ำสองเท่า | ใช้ `ReactDOM.preload` |
| ลืมผสาน metadata ระดับรากที่ Next ผสานให้เอง | แท็ก `keywords` หายจากหน้าที่ย้ายไป โดยไม่มีด่านไหนฟ้อง | INC-0168 |
| ลิงก์ไปหน้า Astro ด้วย `next/link` | ทุกคลิกยิงขอ RSC ที่ไม่มีอยู่จริงก่อนหนึ่งเส้น | ใช้ `RouteLink` |
| ตั้งงบน้ำหนักจากตัวเลขบนเครื่องตัวเอง | ผ่านบนเครื่อง แต่ตกที่ CI ทั้ง 5 เส้นทาง (ต่างกัน 8–9 KB) | INC-0169 |

> 💡 **ข้อเสนอที่ยังไม่ได้ทำ (ต้องให้เจ้าของเคาะ)**: รีโปนี้ไม่มี lockfile โดยตั้งใจ
> CI จึงติดตั้ง dependency รุ่นใหม่กว่าเครื่อง dev ได้เสมอ และขนาดบันเดิลก็ต่างกันตามไปด้วย
> ถ้าอยากให้สองฝั่งตรงกันจริง ต้องตรึงรุ่น `react`/`react-dom` แบบเป๊ะ หรือ commit lockfile
> — เป็นการตัดสินใจระดับรีโปที่กระทบทุกอย่าง จึงไม่ได้ทำเองในรอบนี้

## 5. สิ่งที่ยัง **ไม่ได้** พิสูจน์บนเครื่อง (ต้องตรวจหลัง deploy)

เครื่องที่ทำงานรอบนี้เป็น macOS 12.6 ซึ่ง **รัน workerd ไม่ได้** (ต้องการ 13.5+)
จึงเปิด `opennextjs-cloudflare preview` ไม่ได้เลย · สิ่งที่ตรวจแทนคือเสิร์ฟ
`.open-next/assets` ด้วยเซิร์ฟเวอร์ static ธรรมดาแล้วยิงจริงผ่านเบราว์เซอร์ (ผ่านทุกหน้า)

**เช็กลิสต์ 5 ข้อหลัง deploy รอบแรก** (ใช้เวลาไม่ถึงสองนาที):

```bash
curl -sI https://seertarot.net/cards/major-00 | grep -i "content-security-policy\|cache-control"
curl -sI https://seertarot.net/cards/major-00.jpg | grep -i cache-control   # ต้องมี immutable
curl -sI https://seertarot.net/cards/            | head -1                  # ต้อง 301 ไป /cards
curl -s  https://seertarot.net/cards/major-00 | grep -c astro-island        # ต้องได้ 3
curl -sI https://seertarot.net/daily | grep -i x-nextjs-cache               # หน้าแอปต้องยังผ่าน Worker
```

ถ้าข้อใดข้อหนึ่งไม่ผ่าน ให้ย้อนกลับด้วยการ revert คอมมิตเดียว — หน้าเก่ายังอยู่ครบใน git
และ `ASTRO_ROUTE_PREFIXES` กับ `page.tsx` ที่ลบไปกลับมาพร้อมกันเสมอ
